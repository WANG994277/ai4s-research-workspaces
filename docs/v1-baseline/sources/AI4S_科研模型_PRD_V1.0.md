# AI4S 科研模型 PRD V1.0

> 版本：V1.0  
> 产品名称：AI4S 科研平台  
> 模块名称：科研模型  
> 适用角色：科研人员、项目/课题负责人；科研管理人员、科研决策人员以查看为主；平台管理员负责模型治理  
> 设计基线：科研模型采用“模型广场”模式，面向科研人员提供模型发现、理解、试用、调用和进入 Unified Research Agent 的能力入口；AI4S 不重复建设模型训练、部署和开发能力，创建/训练/发布能力复用 AI 中台。  
> 本文档用途：作为原型、UI、前端、后端、权限、模型接入、与 AI 中台集成及测试设计的统一开发基线。

# 一、产品定位

科研模型是 AI4S 面向科研人员的科研模型发现与调用入口。

其核心目标是解决以下问题：

1. **平台有哪些科研模型可以用？**
2. **某个模型适合解决什么科研问题？**
3. **模型需要什么输入、会产生什么输出？**
4. **当前用户是否具备调用条件和权限？**
5. **如何将模型直接用于 Research Agent 或当前 Research Task？**

科研模型模块不承担模型开发、训练、调参和底层部署。

---

# 二、核心产品原则

## 2.1 按科研领域组织，不按技术框架组织

前台主分类统一为：

```text
全部
通用
地球科学
合成生物科学
材料科学
其他
```

不将以下内容作为科研人员的一级分类：

```text
PyTorch
TensorFlow
ONNX
API
GPU Model
Container
Endpoint
```

这些可作为后台技术属性或详情信息。

---

## 2.2 模型广场的核心是“发现与使用”

科研模型模块主要负责：

> **发现 → 了解 → 试用 → 调用 → 加入 Research Agent**

模型训练、开发、版本构建和部署由 AI 中台承担。

---

## 2.3 Research Agent 默认可以自动选择模型

科研人员不需要每次任务都先进入模型广场挑选模型。

Research Agent 可以根据：

- 当前科研任务；
- 学科；
- 输入数据；
- 可用资源；
- 权限；
- 模型适用范围；

自动选择可用模型。

模型广场主要服务于：

- 主动发现；
- 理解模型能力；
- 高级用户指定模型；
- 项目模型复用；
- 专业模型资产展示。

---

## 2.4 科研模型与科研资产分工不同

> **科研模型：平台有哪些可以发现和调用的模型。**  
> **科研资产：我或当前项目拥有哪些模型资产。**

一个模型对象可先存在于：

> 我的资产 / 项目资产

经过发布后进入：

> 科研模型广场

底层不重复创建模型对象。

# 十二、模型详情页

模型详情需要重点回答：

1. **模型能解决什么问题？**
2. **适合什么科研场景？**
3. **需要什么输入？**
4. **输出什么结果？**
5. **模型是否可靠、经过什么验证？**
6. **当前用户是否有权限和运行条件？**

---

## 12.1 基础信息

包括：

- 模型名称；
- 简介；
- 所属学科；
- 模型类型；
- 能力标签；
- 发布方；
- 来源；
- 当前版本；
- 更新时间；
- 可用状态；
- 可见范围。

---

## 12.2 适用场景

例如：

```text
适用于：
- 页岩气甜点区预测；
- 储层综合评价；
- 多源地质数据融合分析。
```

---

## 12.3 输入说明

应采用科研人员可理解的业务描述。

例如：

```text
输入：
- 测井数据
- 地震属性数据
- 储层参数表
```

而不是只展示接口字段。

---

## 12.4 输出说明

例如：

```text
输出：
- 甜点区预测结果
- 预测概率
- 关键影响因素
- 空间分布结果
```

---

## 12.5 模型验证信息

建议展示：

- 适用范围；
- 验证数据来源；
- 验证状态；
- 关键性能指标；
- 版本说明；
- 使用限制。

不要求统一强制使用同一种模型指标。

不同模型根据自身类型展示相关指标。

# 十六、模型运行与长任务

部分模型可能：

- 秒级返回；
- 分钟级返回；
- 长时间运行。

---

## 16.1 即时模型

直接在当前会话或试用页面返回结果。

不单独创建 Research Task。

---

## 16.2 长周期模型

如果模型执行属于：

- 长时间计算；
- 异步运行；
- 资源等待；
- 多阶段执行；

则：

```text
模型调用
↓
Task Execution
↓
进入当前 Research Task
↓
工作台“当前研究”持续跟踪
```

不在模型广场额外建设一套任务中心。

# 二十二、模型发布规则

模型正式发布前至少满足：

- 基础信息完整；
- 输入输出说明完整；
- 版本明确；
- 来源明确；
- 可正常调用；

- 适用范围明确；
- 通过发布审核。

# 二十六、跨空间模型共享

项目资产模块负责共享管理。

例如：

```text
课题 A 模型
↓
共享至课题 B
↓
课题 B 用户可调用
```

权限至少支持：

```text
只读
可调用
可复制
可协作维护
```

科研模型广场不承担项目内部共享管理。

---

# 二十七、模型调用权限校验

调用前必须检查：

1. 用户是否有模型权限；
2. 当前 Space 是否允许调用；
3. 输入数据是否有权限；
4. 模型依赖资源是否可访问；
5. 是否满足运行资源要求；
6. 模型当前是否可用。

Research Agent 不得绕过这些校验。

---

# 二十八、模型运行资源

AI4S 不直接承担底层算力调度。

用户侧只需看到：

```text
可立即运行
等待资源
资源不足
暂不可用
```

具体：

- GPU；
- CPU；
- 容器；
- 队列；
- 推理服务；

由 AI 中台管理。

# 三十九、核心验收标准

## 39.1 模型广场

- [ ] 支持全部、通用、地球科学、合成生物科学、材料科学、其他分类；
- [ ] 支持搜索；
- [ ] 支持筛选；
- [ ] 模型卡片展示科研人员需要的信息；
- [ ] 不按照技术框架组织主导航。

---

## 39.2 模型详情

- [ ] 明确展示模型解决什么问题；
- [ ] 明确展示适用场景；
- [ ] 明确展示输入；
- [ ] 明确展示输出；
- [ ] 展示当前版本；
- [ ] 展示模型验证信息；
- [ ] 展示使用限制和可用范围。

---

## 39.3 调用

- [ ] 支持直接试用；
- [ ] 支持加入 Research Agent；
- [ ] 支持加入当前 Research Task；
- [ ] Research Agent 可以自动调用；
- [ ] 调用前完成 Model ACL 和依赖权限校验。

---

## 39.4 长任务

- [ ] 即时模型不制造额外任务卡片；
- [ ] 长周期模型执行可自动进入当前研究；
- [ ] 支持等待资源；
- [ ] 支持后台运行；
- [ ] 可恢复执行状态。

---

## 39.5 创建与资产

- [ ] AI4S 不建设模型训练和开发环境；
- [ ] 创建模型跳转 AI 中台；
- [ ] 创建结果回流我的资产 / 项目资产；
- [ ] 正式发布后进入模型广场；
- [ ] 模型广场与科研资产底层不重复建对象。

---

## 39.6 权限

- [ ] 项目模型按 Project / Space 权限控制；
- [ ] 跨课题模型需要授权；
- [ ] 输入数据权限必须同时校验；
- [ ] Research Agent 不得绕过模型 ACL；
- [ ] 无权限模型不得执行。

# 四十、最终产品基线

科研模型最终定义为：

> **AI4S 中面向科研人员的科研模型发现与调用入口，以通用、地球科学、合成生物科学、材料科学和其他为主要分类，支持模型搜索、查看详情、试用、调用并直接加入 Unified Research Agent 或当前 Research Task；模型创建、训练、调试和部署能力复用 AI 中台，个人和项目形成的模型统一沉淀至科研资产，正式发布后进入科研模型广场。**

核心链路统一为：

> **发现模型 → 了解模型 → 调用模型 → 进入科研任务 → 形成科研结果 → 沉淀科研资产。**
