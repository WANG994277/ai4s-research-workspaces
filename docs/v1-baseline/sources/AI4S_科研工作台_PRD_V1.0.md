# AI4S 科研工作台 PRD V1.0

> 版本：V1.0  
> 产品名称：AI4S 科研平台  
> 模块名称：科研工作台 / Unified Research Agent Workspace  
> 适用角色：科研人员、项目/课题负责人（基础科研工作能力一致，负责人叠加管理能力）  
> 设计基线：以 Unified Research Agent 为唯一主入口；取消前台“读/算/做”独立空间；工作台采用“科研执行型”方案，不纳入科研资讯、前沿文献、专利动态等资讯流内容。  
> 本文档用途：作为原型、UI、前端、后端、Agent 编排、权限和测试设计的统一开发基线。

---

# 一、产品定位

科研工作台是 AI4S 面向科研人员的核心首页和统一科研任务入口。

其核心目标不是展示大量统计指标，也不是提供传统 Dashboard，而是帮助科研人员完成以下三件事：

1. **发起科研任务；**
2. **持续推进需要跟踪的科研工作；**
3. **处理需要人工介入的关键节点并获取科研产出。**

工作台统一回答三个问题：

> **有什么等我处理？**  
> **我的研究进行到哪了？**  
> **我最近产出了什么？**

---

# 二、核心产品原则

## 2.1 Unified Research Agent 是唯一主入口

科研人员不需要主动选择：

```text
读空间
算空间
做空间
```

统一通过 Research Agent 发起任务。

Research Agent 在后台根据任务自动规划并调用：

- 专业 Agent / SubAgent；
- Skill；
- 科研模型；
- 数据集；
- 科研软件；
- 工具；
- MCP / Connector；
- 知识资源；
- 云上实验室相关能力。

前台只适度展示执行过程，不要求用户理解底层技术编排。

---

## 2.2 以科研任务为中心，而不是以能力分类为中心

用户首先表达：

> “我要解决什么科研问题？”

而不是：

> “我要用哪个工具？”

工具、模型、Skill、Agent 作为可调用资源存在。

---

## 2.3 瞬时任务不制造任务管理负担

以下任务默认只作为历史会话保存，不进入“当前研究”：

- 简单问答；
- 单篇文献总结；
- 翻译；
- 简单计算；
- 一次性检索；
- 秒级或分钟级可直接完成的普通任务。

只有满足以下任一特征的任务，才进入“当前研究”：

- 长周期；
- 异步执行；
- 多步骤；
- 需要持续跟踪；
- 需要后台运行；
- 需要人工介入；
- 具有明确科研阶段性；
- 会形成正式科研产出。

---

## 2.4 Space 决定上下文，不改变产品基本交互

工作台始终保持同一结构。

切换空间后，只改变：

- Agent 上下文；
- 数据权限；
- 历史会话；
- Research Task；
- 科研资产；
- 可调用资源；
- 协作成员；
- 待处理事项。

不为每一种 Space 重新设计一套工作台。

---

# 三、目标用户

## 3.1 科研人员

主要需求：

- 快速发起科研任务；
- 让 Agent 自动调用资源完成复杂研究任务；
- 随时恢复历史研究；
- 跟踪长周期任务；
- 处理 AI 无法自动完成的决策节点；
- 获取并沉淀科研产出。

---

## 3.2 项目/课题负责人

在科研人员基础能力上，额外关注：

- 当前课题中的协作科研任务；
- 团队科研成果；
- 需要负责人确认的关键节点；
- 项目/课题范围内授权科研资产。

负责人仍然使用同一 Research Agent 工作台，不单独建设另一套工作台。

---

# 四、产品边界

## 4.1 本模块负责

- Unified Research Agent 主会话；
- 空间切换；
- 历史会话；
- 科研任务发起；
- 长周期 Research Task 跟踪；
- Agent 执行轨迹；
- Human-in-the-loop 人工决策；
- 最近科研产出；
- 科研上下文引用；
- 已有科研资源调用；
- Research Artifact / Asset 关联；
- 会话恢复；
- 任务恢复。

---

## 4.2 本模块不负责

- Agent 开发；
- Skill 开发；
- 模型训练；
- 数据集创建；
- 底层算力管理；
- 完整科研项目管理；
- 科研立项 / 经费 / 合同 / 验收；
- 科研资讯流；
- 前沿文献推荐流；
- 专利动态资讯流；
- 传统科研驾驶舱。

以上能力分别由 AI 中台、科研项目管理系统或其他模块承担。

# 五、页面整体结构

工作台采用：

```text
┌──────────────────────────────────────────────────────────┐
│ 顶栏                                      当前空间 ▾      │
├──────────────┬───────────────────────────────────────────┤
│              │                                           │
│ 历史会话栏    │          Unified Research Agent           │
│              │                                           │
│ + 新建任务    │          主输入区 / 当前会话              │
│ 搜索会话      │                                           │
│ 最近会话      │                                           │
│              │                                           │
├──────────────┴───────────────────────────────────────────┤
│ 需要我处理                                               │
├──────────────────────────────────────────────────────────┤
│ 当前研究                                                 │
├──────────────────────────────────────────────────────────┤
│ 最近科研产出                                             │
└──────────────────────────────────────────────────────────┘
```

主会话进入执行状态后，页面可以切换为专注会话模式，下方工作台内容折叠或移出首屏。

# 六、顶栏设计

## 6.1 顶栏元素

建议保留：

- AI4S Logo / 产品名称；
- 当前页面名称；
- 当前空间切换器；
- 消息 / 通知；
- 用户头像。

避免在顶栏堆叠大量快捷入口。

---

# 七、空间切换器

## 7.1 入口位置

固定在工作台右上角。

示例：

```text
当前空间：页岩气储层评价课题 ▾
```

---

## 7.2 空间层级

空间选择面板建议按科研项目分组：

```text
个人空间

非常规油气前沿研究
├─ 项目空间
├─ 页岩气储层评价课题
├─ 压裂机理研究课题
└─ 储层预测研究课题

CCUS材料研究
├─ 项目空间
└─ CO₂吸附材料课题
```

---

## 7.3 支持的空间类型

```text
PERSONAL
PROJECT
TOPIC
```

分别对应：

- 个人空间；
- 项目空间；
- 课题空间。

---

## 7.4 切换空间后的联动

空间切换成功后必须刷新：

1. 历史会话；
2. 当前研究；
3. 需要我处理；
4. 最近科研产出；
5. 可访问项目资产；
6. 可访问知识资源；
7. 可调用 Skill / Model / Tool；
8. 当前 Agent 上下文；
9. 当前协作成员。

---

## 7.5 切换中的异常处理

如当前会话有未保存状态：

弹窗提示：

```text
当前会话尚有未保存内容。
切换空间后，当前会话仍会保留在原空间。

[取消] [继续切换]
```

不得直接迁移当前会话到新 Space。

---

# 八、历史会话侧栏

## 8.1 页面定位

历史会话用于：

> **恢复科研过程和连续上下文。**

不是一个新的一级业务模块。

---

## 8.2 信息结构

```text
+ 新建科研任务

搜索历史会话

今天
- 非常规油气前沿调研
- 催化剂方案优化

最近7天
- 页岩气敏感性分析
- CCUS专利分析

更早
- ……

查看全部
```

---

## 8.3 默认数据范围

默认显示：

> **当前 Space 下本人有权访问的历史会话。**

支持切换：

```text
当前空间
全部有权空间
```

“全部有权空间”主要用于搜索，不建议默认展示。

---

## 8.4 会话操作

单条会话支持：

- 打开；
- 重命名；
- 收藏；
- 分享；
- 归档；
- 删除。

删除需要二次确认。

---

## 8.5 会话可见性

默认：

```text
PRIVATE
```

可主动修改为：

```text
SHARED
COLLABORATIVE
```

空间共享不等于会话自动共享。

# 九、Unified Research Agent 主入口

## 9.1 空状态

主标题：

> **今天想推进什么科研任务？**

输入框作为页面绝对视觉核心。

---

## 9.2 输入能力

支持：

- 文字输入；
- 多文件上传；
- 图片上传；
- 文档拖拽；
- 粘贴内容；
- 引用已有科研资产；
- 引用知识中心内容；
- 引用数据；
- @资源。

---

## 9.3 输入框一级操作

控制在四类：

```text
附件
科研上下文
调用能力
研究模式
```

避免一级铺开：

```text
Agent / Skill / MCP / Model / Tool / Software / Dataset
```

---

# 十、科研上下文

## 10.1 入口

点击：

> **科研上下文**

打开侧边面板或 Popover。

---

## 10.2 可关联对象

包括：

- 当前科研项目；
- 当前课题；
- 知识资源；
- 项目资产；
- 我的资产；
- 数据集；
- 历史科研产出；
- 指定历史会话；
- 已授权跨课题资产。

---

## 10.3 默认上下文

Research Agent 默认继承：

```text
Current User
+
Current Project
+
Current Space
+
用户明确选择的上下文
```

不默认加载整个项目所有数据。

---

## 10.4 上下文可见性

会话顶部或输入框附近以轻量方式展示：

```text
上下文：
页岩气储层评价课题 ×
实验数据集 V2 ×
储层评价研究报告 ×
```

支持删除某项上下文。

# 十一、调用能力

## 11.1 设计原则

Research Agent 默认自动决定调用什么能力。

用户无需在发起任务前完成复杂配置。

“调用能力”主要用于高级用户主动指定。

---

## 11.2 支持类型

```text
Agent
Skill
Model
Tool
Software
Dataset
MCP / Connector
```

---

## 11.3 能力选择交互

点击“调用能力”后打开统一选择器：

```text
搜索能力……

最近使用
推荐能力
按学科
按类型
```

用户选择后以 Chip 形式显示在输入框。

---

# 十二、研究模式

V1.0 建议只保留少量清晰模式，避免技术化。

建议：

```text
自动
深度研究
快速分析
```

### 自动

默认模式，由 Agent 自主判断任务复杂度。

### 深度研究

适用于：

- 多步骤研究；
- 多来源综合；
- 长周期分析；
- 需要形成正式科研产出。

### 快速分析

适用于轻量任务。

不要在 V1.0 堆叠大量模式。

---

# 十三、任务提交后的 Agent 会话

用户发送任务后进入主会话界面。

建议结构：

```text
用户任务
   ↓
Agent理解 / 简要计划
   ↓
执行过程
   ↓
必要时人工确认
   ↓
结果
   ↓
科研产出
```

---

# 十四、任务规划

对于复杂任务，Agent 应先生成轻量研究计划。

示例：

```text
我将分 4 步完成：
1. 检索近 5 年相关文献；
2. 提取关键影响因素；
3. 对已有实验数据进行统计分析；
4. 综合形成研究建议。
```

用户可以：

- 直接开始；
- 修改计划；
- 添加约束；
- 取消。

对于简单任务不强制展示任务规划。

---

# 十五、Agent 执行轨迹

## 15.1 设计目标

轨迹需要：

> **可查看、可解释、可追溯，但不把后台技术日志完整暴露给用户。**

---

## 15.2 前台建议展示

例如：

```text
✓ 检索相关文献 42 篇
✓ 筛选高相关文献 18 篇
● 正在分析储层影响因素
○ 运行敏感性计算
○ 综合研究结论
```

---

## 15.3 默认展示层级

默认只展示：

- 当前步骤；
- 已完成步骤；
- 下一步；
- 关键调用对象；
- 错误 / 等待状态。

详细日志放入：

> 查看执行详情

---

## 15.4 可追溯信息

关键步骤支持查看：

- 使用的数据；
- 使用的文献；
- 调用的 Skill；
- 调用的 Model；
- 调用的 Tool；
- 运行时间；
- 输出对象；
- 来源。

---

# 十六、Research Task 创建规则

## 16.1 自动创建

Agent 判断任务为以下类型时自动创建 Research Task：

- 长周期；
- 异步；
- 多步骤；
- 需要持续运行；
- 需要人工介入；
- 会产生阶段性科研产出。

---

## 16.2 不创建 Research Task

普通即时任务：

```text
用户提问
↓
Agent回答
↓
历史会话保存
```

不进入“当前研究”。

---

## 16.3 创建提示

无需打断用户。

任务进入持续执行后，系统轻提示：

> 已作为持续科研任务跟踪，可在“当前研究”中查看进度。

---

# 十七、任务状态

统一建议状态：

```text
规划中
运行中
等待人工处理
等待资源
已暂停
执行失败
已完成
已取消
```

后端建议对应：

```text
PLANNING
RUNNING
WAITING_HUMAN
WAITING_RESOURCE
PAUSED
FAILED
COMPLETED
CANCELLED
```

---

# 十八、人工决策 Human-in-the-loop

## 18.1 触发条件

仅在 Agent 无法合理自动决策或必须由人承担责任时触发。

典型场景：

- 研究假设选择；
- 参数确认；
- 实验方案确认；
- 数据权限确认；
- 资源消耗确认；
- 结果异常判断；
- 跨空间共享；
- 高风险操作确认。

---

## 18.2 交互方式

采用：

> **底部抽屉 / Bottom Sheet**

不新开复杂页面。

---

## 18.3 底部抽屉结构

```text
需要你确认

问题：
本次模拟检测到两个可行参数范围。

Agent 建议：
优先采用方案 B。

原因：
……

选项：
○ 方案 A
● 方案 B
○ 自定义

[暂不处理] [确认并继续]
```

---

## 18.4 决策记录

需要记录：

- 决策问题；
- Agent 建议；
- 用户选择；
- 决策人；
- 时间；
- 对应 Task Step。

用于科研过程追溯。

---

# 十九、需要我处理

## 19.1 模块定位

工作台下方优先级最高的业务区。

回答：

> **“现在有什么事情必须由我处理？”**

---

## 19.2 准入规则

只展示：

- WAITING_HUMAN；
- 明确需要本人审批 / 判断 / 确认；
- 明确 @本人；
- 明确需要本人授权的事项。

普通通知不进入。

---

## 19.3 卡片字段

建议每条包含：

- 事项名称；
- 所属项目 / 课题；
- 关联 Research Task；
- 为什么需要处理；
- Agent 建议；
- 紧急程度；
- 时间；
- 主操作。

例如：

```text
催化剂实验方案 V3 待确认
CO₂催化材料课题

Agent建议：将反应温度由 450℃ 调整为 430℃。
原因：前两轮实验结果显示……

[查看并处理]
```

---

## 19.4 处理后

处理完成后：

- 从“需要我处理”移除；
- Research Task 恢复运行；
- 会话中记录人工决策；
- 生成审计记录。

---

# 二十、当前研究

## 20.1 模块定位

展示：

> **值得持续跟踪、尚未结束的 Research Task。**

不是所有历史任务。

---

## 20.2 数据范围

默认：

> 当前 Space 下本人创建、本人参与、本人负责或明确共享给本人的任务。

项目/课题负责人可根据权限看到：

> 所负责空间内需要关注的协同科研任务。

---

## 20.3 卡片字段

建议包含：

- Research Task 名称；
- 任务类型；
- 所属项目 / 课题；
- 当前阶段；
- 当前状态；
- 进度；
- 最近更新时间；
- 下一步；
- 主操作。

例如：

```text
页岩气储层敏感性分析
科学计算 · 页岩气储层评价课题

运行中 · 68%
当前：正在运行敏感性模拟
最近更新：3分钟前

[查看运行]
```

---

## 20.4 排序

默认优先级：

1. 等待人工处理；
2. 运行中；
3. 等待资源；
4. 最近更新。

已完成任务不进入“当前研究”。

---

# 二十一、最近科研产出

## 21.1 模块定位

回答：

> **“最近形成了什么值得继续使用的科研结果？”**

---

## 21.2 准入规则

只有形成明确 Research Artifact / Research Asset 的对象才展示。

不展示普通聊天回答。

---

## 21.3 产出类型

包括：

- 文献综述；
- 研究假设；
- 数据分析结果；
- 图表；
- 计算结果；
- 实验方案；
- 科研报告；

# 三十三、通知规则

# 三十六、核心验收标准

## 36.1 工作台首页

- [ ] 工作台顶部存在统一 Research Agent 输入入口；
- [ ] 不出现读 / 算 / 做三个独立入口；

- [ ] 左侧支持历史会话；
- [ ] 下方仅包含“需要我处理 / 当前研究 / 最近科研产出”；
- [ ] 不出现科研资讯、前沿资讯、专利资讯流。

## 36.2 Agent

- [ ] 支持文本和文件输入；
- [ ] 支持科研上下文引用；
- [ ] 支持主动指定能力；
- [ ] 支持 Agent 自动调用 Skill / Model / Tool；
- [ ] 支持任务规划；
- [ ] 支持执行轨迹；
- [ ] 支持长任务异步运行。

## 36.3 当前研究

- [ ] 瞬时任务不进入当前研究；

- [ ] Agent 可发起人工决策；

## 36.5 最近科研产出

## 36.6 权限

- [ ] Agent 不得绕过 Project / Space / Asset ACL；

- [ ] 空间切换后数据范围正确更新；
- [ ] 跨空间资产仅在明确授权后可调用。

# 三十八、最终产品基线

科研工作台最终定义为：

> **以 Unified Research Agent 为核心入口，以当前科研空间作为上下文和权限边界，让科研人员通过自然语言持续推进科研任务；平台自动调度知识、Skill、模型、工具、软件、数据和实验能力，仅对长周期、多步骤、异步或需要人工介入的科研任务进行持续跟踪，并将有价值的研究结果沉淀为可追溯、可复用的科研资产。**

工作台首页始终围绕三个核心问题组织：

> **有什么等我处理？**  
> **我的研究进行到哪了？**  
> **我最近产出了什么？**
