# AI4S 原型重构与产品设计基线 V1.0

> 版本：V1.0（基线重构版）  
> 产品名称：AI4S 科研平台  
> 文档性质：原型、UI、产品交互和页面设计统一约束  
> 继承基线：核心对象模型、角色权限矩阵、新版信息架构 IA、各一级模块 PRD V1.0  
> 核心原则：**严格继承现有术语、模块边界、角色权限和对象模型；允许补齐实现必需的交互状态，但不得借“补全需求”重新扩展业务范围。**

---

# 1. 文档目标

本文件用于解决 AI4S 原型持续迭代过程中容易出现的以下问题：

1. AI 根据局部需求自行新增未定义页面或业务模块；
2. 不同页面套用同一 Dashboard 模板，业务工作模式失真；
3. 一级、二级、详情页、交互状态颗粒度混杂；
4. 同一个对象在不同模块重复建设；
5. 为不同角色重复设计整套页面，而不是通过权限和数据范围形成差异；
6. 将 MCP、API、模型框架等技术概念直接暴露为科研人员主导航；
7. 页面按钮、注释、小字、统计卡片和装饰信息过多，主任务不突出；
8. 重复建设 AI 中台、科研项目管理系统、LIMS / ELN 等已有系统能力；
9. 混淆 Agent Session、Research Task、Research Artifact、Research Asset；
10. 原型只表现“页面长什么样”，但没有落实对象、状态、权限和下一步操作。

---

# 2. 不可变产品基线

以下内容属于原型重构的硬约束。

## 2.1 一级业务模块不得自行增删改名

```text
科研工作台
知识中心
科研技能
科研模型
科研工具箱
云上实验室
科研资产
项目空间管理
科研管理工作台
科研决策工作台 / 科研驾驶舱
科研项目管理【集成】
平台管理后台
```

页面分组标题可以调整，但不得把分组标题重新定义为新的业务模块。

---

## 2.2 Unified Research Agent 是科研执行唯一主入口

科研工作台必须保持：

```text
用户科研问题
    ↓
Unified Research Agent
    ↓
自动或指定调用
Agent / Skill / Model / Dataset / Tool / Software / MCP / Knowledge / Experiment
    ↓
Research Task / Research Artifact / Research Asset
```

禁止重新恢复：

```text
读空间
算空间
做空间
```

作为三个并列主入口或三个独立 Main Agent。

“读、算、做”只能作为后台能力域、任务步骤或研究过程概念存在。

---

## 2.3 核心对象必须严格区分

### Agent Session

用户与 Unified Research Agent 的连续会话。

### Research Task

需要持续推进、跟踪、异步执行、人工介入或形成正式科研产出的科研任务。

### Task Step

Research Task 的具体执行步骤。

### Research Artifact

科研过程中产生的中间或阶段性产物。

### Research Asset

经保存、确认、版本化后进入正式管理体系的科研资产。

原型不得用一个笼统的“任务”或“成果”覆盖上述对象。

---

## 2.4 Project 与 Space 不得混用

```text
Project = 正式科研项目的逻辑业务边界
Space   = 科研上下文、成员协作和权限访问范围承载单元
```

空间类型固定为：

```text
PERSONAL
PROJECT
TOPIC
```

一个 Project 原则上：

```text
1 个 Project Space
N 个 Topic Space
```

不得设计新的“团队空间”“实验空间”“模型空间”等并列空间类型。

---

## 2.5 科研资产范围不得扩张

V1.0 正式资产类型重点为：

```text
智能体
Skill
模型
数据集
方案模板
```

“科研报告、图表、实验结果”等可先作为 Research Artifact 存在；是否纳入新的正式资产类型，应以后续明确基线为准，不在原型阶段自行扩展 Asset Type。

科研资产一级固定为：

```text
我的资产
项目资产
```

项目资产内部通过筛选区分：

```text
当前课题
项目公共
其他课题授权共享
```

---

## 2.6 云上实验室范围固定为四项

```text
仪器设备纳管
仪器设备共享
实验任务管理
实验试剂耗材管理
```

禁止原型自行增加：

- 样品管理；
- 实验方案中心；
- 分析化验独立门户；
- 自动化实验工作流；
- 实验室安全管理；
- 试剂采购；
- 仓储物流；
- LIMS / ELN 全量功能。

---

## 2.7 项目空间管理只做空间治理

固定二级功能：

```text
项目空间
课题空间
空间成员
角色与权限
空间配置
```

不得扩展为完整科研项目管理系统。

---

# 3. “允许补全”与“禁止扩展”的判断规则

## 3.1 PRD 有遗漏时允许补全的内容

AI 可以自行补齐以下实现必需内容：

- 空状态；
- Loading / Skeleton；
- 网络失败状态；
- 外部系统异常状态；
- 无权限状态；
- 表单校验；
- 二次确认；
- 删除 / 归档风险提示；
- 分页；
- 搜索；
- 基础筛选；
- 基础排序；
- 列表与详情之间的返回关系；
- 已定义业务对象的详情信息分组；
- 长任务运行状态恢复；
- 任务失败重试；
- 上传进度；
- 操作成功 / 失败反馈；
- 已定义对象之间的关联展示；
- 外部系统跳转和回流状态。

这些属于“实现完整性补齐”，不视为新增业务功能。

---

## 3.2 不允许 AI 自行补全的内容

以下内容必须有明确需求才能新增：

- 新一级模块；
- 新二级业务域；
- 新核心业务对象；
- 新空间类型；
- 新系统角色；
- 新审批链；
- 新资产类型；
- 新实验业务域；
- 新项目生命周期；
- 新社区 / 评论 / 排行榜；
- 新积分 / 激励体系；
- 新运营中心；
- 新资讯流；
- 新数据采集平台；
- 新模型训练功能；
- 新 Skill 开发器；
- 新工作流编排平台；
- 新任务中心；
- 新消息中心业务体系。

遇到 PRD 不完整时，优先顺序必须是：

```text
复用现有对象
→ 复用现有公共组件
→ 复用现有模块
→ 跳转 / 集成外部系统
→ 最后才考虑新增能力
```

# 4. 全局原型骨架

## 4.1 平台级 App Shell

推荐结构：

```text
┌─────────────────────────────────────────────────────────────┐
│ Logo / AI4S     页面标题                 当前空间 ▾  通知 用户 │
├───────────────┬─────────────────────────────────────────────┤
│ 一级导航       │                                             │
│               │                页面主工作区                  │
│               │                                             │
└───────────────┴─────────────────────────────────────────────┘
```

全局顶栏重点只保留：

- 产品标识；
- 当前页面；
- Space 切换器；
- 必要通知；
- 用户入口。

不得堆叠大量快捷操作。

---

## 4.2 科研工作台专用骨架

科研工作台可使用：

```text
┌──────────────┬─────────────────────────────────────────────┐
│ 历史会话      │ Unified Research Agent                     │
│ + 新建任务    │                                             │
│ 搜索会话      │ 主输入 / 当前会话 / 执行轨迹 / 产出         │
│ 最近会话      │                                             │
└──────────────┴─────────────────────────────────────────────┘
```

空状态首页下方再承载：

```text
需要我处理
当前研究
最近科研产出
```

进入深度会话后，不要求同时把首页三个区块持续固定在首屏。

# 5. 页面设计前置分析法

任何页面开始设计前，必须先回答五个问题。

| 问题 | 要求 |
|---|---|
| 用户是谁 | 明确当前角色和数据范围 |
| 当前任务是什么 | 页面必须服务一个主任务 |
| 当前主对象是什么 | 明确 Project / Task / Asset / Instrument 等 |
| 主操作是什么 | 首屏最多 1 个强主操作，必要时 1～2 个次操作 |
| 下一步去哪里 | 明确完成后的对象状态与跳转 |

如果上述五项无法回答，禁止直接套通用 Dashboard。

---

# 6. 页面工作模式分类

全平台页面优先归入以下工作模式，而不是统一套一个视觉模板。

## 6.1 Agent Workspace 型

适用：科研工作台。

核心：

- 对话；
- 上下文；
- 任务规划；
- 执行轨迹；
- Human-in-the-loop；
- 产出。

视觉中心必须是用户当前研究任务，不是统计数字。

---

## 6.2 Search / Discovery 型

适用：

- 知识中心；
- 科研技能；
- 科研模型；
- 科研工具箱；
- 仪器设备共享。

标准骨架：

```text
核心检索入口
→ 分类 / 筛选
→ 结果列表 / 卡片
→ 详情
→ 使用 / 引用 / 加入 Research Agent
```

不得在顶部先放大量统计卡片。

---

## 6.3 Asset Management 型

适用：科研资产。

核心：

- 资产归属；
- 类型；
- 版本；
- 分享；
- 发布；
- 使用；
- 来源追溯。

优先使用列表 / 表格 + 详情页，不做“资源商城”。

---

## 6.4 Resource Management 型

适用：

- 仪器设备纳管；
- 实验任务；
- 试剂耗材；
- 项目空间；
- 空间成员；
- 角色与权限。

优先使用：

```text
列表
→ 详情
→ 状态
→ 授权操作
```

强调可管理性和状态，不强调营销式卡片。

---

## 6.5 Management Workbench 型

适用：科研管理工作台。

核心：

```text
管理概览
→ 需要关注
→ 项目运行
→ 科研进展
→ 风险与异常
→ 科研成果
```

页面只聚合已有科研执行对象，不制造新的“管理任务体系”。

---

## 6.6 Decision Cockpit 型

适用：科研决策工作台 / 科研驾驶舱。

核心：

```text
总体态势
→ 重大项目
→ 风险与异常
→ 科研成果
→ 科研资源
→ 下钻查看
```

强调跨项目态势和只读分析，不建设日常编辑能力。

---

## 6.7 External Integration 型

适用：科研项目管理、AI 中台开发能力、外部软件等。

页面必须明确：

- 来源系统；
- 当前同步状态；
- 本平台负责什么；
- 哪个操作需要跳转；
- 跳转后如何回流。

禁止用“占位页面”伪装成 AI4S 已建设完整功能。

---

# 7. 信息密度与层级规范

## 7.1 首屏原则

首屏只放与当前主任务直接相关的信息。

不允许：

- 统计卡片横向铺满；
- 同一层出现 6～10 个同权按钮；
- 大段解释型小字；
- 为“看起来丰富”增加不产生操作价值的装饰字段；
- 把二级、三级功能全部摊平。

---

## 7.2 渐进披露

信息优先级：

```text
主任务
→ 当前状态
→ 主操作
→ 关键依据
→ 次级信息
→ 详细配置 / 技术信息
```

复杂内容默认进入：

- 侧边面板；
- 抽屉；
- 详情 Tab；
- “查看详情”；
- 高级筛选。

---

## 7.3 操作层级

### Primary

一个页面原则上只有一个视觉最强的主操作。

### Secondary

与当前任务强相关的辅助操作。

### Tertiary

放入更多菜单、详情区或次级链接。

危险操作：

- 删除；
- 关闭；
- 取消任务；
- 撤销共享；
- 下架；

必须弱化常态曝光，并在执行时二次确认。

---

# 8. 列表、卡片与表格使用原则

## 8.1 卡片

适合：

- Skill；
- Model；
- Tool；
- 共享仪器；
- 少量科研产出。

卡片最多突出：

```text
名称
一句话能力 / 用途
2～4 个关键属性
当前状态
主操作
```

---

## 8.2 表格

适合：

- 项目空间；
- 空间成员；
- 仪器设备纳管；
- 实验任务；
- 试剂耗材；
- 项目运行；
- 管理 / 决策下钻列表。

表格不要同时展示全部后台字段。

---

## 8.3 列表

适合：

- 会话；
- 待处理事项；
- Research Task；
- 检索结果；
- 科研资产。

需要优先保证扫描效率。

---

# 9. Unified Research Agent 原型规则

## 9.1 输入框一级控制固定为四类

```text
附件
科研上下文
调用能力
研究模式
```

禁止把：

```text
Agent / Skill / Model / Tool / MCP / Software / Dataset
```

全部做成输入框并列一级按钮。

---

## 9.2 Agent 自动调用优先

普通用户主要表达研究目标。

“调用能力”只为高级用户提供主动指定入口。

---

## 9.3 执行轨迹必须存在，但保持科研语言

默认展示：

- 当前步骤；
- 已完成步骤；
- 下一步；
- 关键调用资源；
- 等待 / 失败；
- 关键来源。

详细技术日志放在“执行详情”，前台不直接暴露底层 Chain-of-Thought、容器日志或系统提示词。

---

## 9.4 Human-in-the-loop 使用底部抽屉

底部抽屉固定包含：

```text
需要确认的问题
Agent 建议
建议原因
可选项
暂不处理
确认并继续
```

不为每个决策创建独立页面。

---

## 9.5 即时任务与持续任务分流

```text
简单问答 / 翻译 / 一次检索
→ Agent Session
→ 历史会话
```

```text
长周期 / 多步骤 / 异步 / 人工介入 / 正式产出
→ Research Task
→ 当前研究
```

原型不得把每次对话都做成任务卡片。

---

# 10. Space 上下文设计规则

## 10.1 全局统一 Space 切换器

在需要 Project / Space 上下文的业务页面统一使用同一个组件。

不得为每个模块单独设计不同的“项目选择器”“课题选择器”“团队选择器”。

---

## 10.2 切换 Space 后联动刷新

至少包括：

- 历史会话；
- Research Task；
- 待处理事项；
- 科研产出；
- 项目资产；
- 内部知识；
- 可调用 Skill / Model / Tool；
- 实验资源；
- 协作成员。

---

## 10.3 不自动迁移对象

切换 Space 不等于修改已有对象的归属。

例如当前 Agent Session 在 Topic Space A 中创建，切换到 Topic Space B 时：

- 原 Session 仍属于 A；
- 新上下文从 B 重新计算；
- 如需跨空间使用资产，必须经过授权。

---

# 11. 权限在原型中的可见表达

权限不能只存在后台数据模型中。

原型至少需要表现：

1. 无权限对象隐藏或受限；
2. “当前权限来自哪里”；
3. 跨课题共享授权；
4. Asset Share 权限级别；
5. 无权限申请入口（仅制度允许时）；
6. Space 成员和 Space Role；
7. 外部服务授权状态；
8. Agent 调用受限资源时的校验失败；
9. 用户被移出 Space 后的数据访问变化。

不得为了“方便演示”让管理员、管理人员或 Agent 默认看到全部私人会话和草稿。

---

# 12. 各模块原型重构重点

## 12.1 科研工作台

必须聚焦：

```text
发起科研任务
需要我处理
当前研究
最近科研产出
```

删除与主任务无关的：

- 资讯流；
- 大量统计；
- 大面积科研趋势；
- 大量独立子 Agent 快捷卡片。

---

## 12.2 知识中心

首屏绝对核心：

> 一站式科研知识检索

支持：

```text
智能检索
关键词检索
高级检索
分子结构式检索
```

知识详情只提供轻量 AI 辅助；复杂分析必须进入 Research Agent。

---

## 12.3 科研技能

采用 Skill 广场：

```text
搜索
学科分类
筛选
Skill 卡片
Skill 详情
试用 / 调用
加入 Research Agent
```

不得重复建设 Skill 开发平台或资产管理。

---

## 12.4 科研模型

采用模型广场：

```text
搜索
学科分类
筛选
模型卡片
模型详情
轻量试用
加入 Research Agent
```

不得设计训练、微调、部署、GPU 配置。

---

## 12.5 科研工具箱

科研人员主认知为科研用途，而非技术协议。

技术标签如 MCP / Connector 可出现在详情或后台，但不作为首页主导航。

---

## 12.6 云上实验室

设备纳管与设备共享必须分开：

```text
设备纳管 = 管设备
设备共享 = 找设备 / 预约设备
```

Experiment Task 必须与 Research Task 区分。

---

## 12.7 科研资产

突出：

```text
归属
版本
分享
发布
引用
来源追溯
```

“分享”和“发布”不得混为一个按钮。

---

## 12.8 项目空间管理

突出：

```text
Project → Space → Membership → Space Role → Permission
```

科研任务和科研资产在空间详情中只做概览和跳转，不重复建设完整管理页面。

---

## 12.9 科研管理工作台

只聚合授权组织 / 项目范围内的已有科研执行对象。

不建设：

- 空间 ACL 后台；
- 私人会话审查；
- 新风险对象体系；
- 完整项目生命周期管理。

---

## 12.10 科研决策工作台 / 科研驾驶舱

必须体现：

> 数据范围广，但直接操作权限少。

以跨项目态势、重大项目、风险异常、成果和科研资源为主。

不得演变成项目编辑后台或人员绩效排名系统。

---

# 13. Mock 数据与原型对象要求

所有高保真原型应使用有业务意义的对象数据，而不是：

```text
项目1
任务A
模型测试
用户123
```

但 Mock 数据必须保持对象字段一致。

建议示例：

```text
Project：非常规油气前沿研究
Topic Space：页岩气储层评价课题
Research Task：页岩气储层敏感性分析
Experiment Task：储层岩样高压吸附实验
Model：页岩储层甜点预测模型 V3.2
Skill：文献证据抽取 Skill
Asset：页岩气实验数据集 V2
```

原型中的对象标识应能映射到：

```text
project_id
space_id
task_id
session_id
artifact_id
asset_id
skill_id
model_id
instrument_id
experiment_task_id
```

无需在普通页面直接展示 ID，但交互说明必须明确当前操作落在哪个对象上。

# 14. 原型状态覆盖规范

关键页面不能只设计“正常态”。

按需要至少覆盖：

```text
正常态
空状态
Loading
无权限
部分数据不可用
外部系统异常
运行中
等待资源
等待人工
失败
已归档 / 已下架
```

只有与业务对象相关的状态才需要设计，不要求所有页面机械覆盖全部状态。

# 15. 文案与术语规范

## 15.1 必须使用正式术语

优先使用：

```text
科研工作台
Unified Research Agent
Research Task
Agent Session
Research Artifact
Research Asset
Project
Space
项目空间
课题空间
科研技能
科研模型
科研工具箱
云上实验室
```

## 15.2 面向科研人员时优先中文业务语言

例如前台状态：

```text
规划中
运行中
等待人工处理
等待资源
已暂停
执行失败
已完成
```

后端枚举可以保留英文。

## 15.3 避免过度解释型文案

不要在每个卡片下增加“帮助用户理解”的长说明。

应通过：

- 清晰标题；
- 一句话说明；
- 状态；
- 主操作；

完成主要表达。

# 16. 给原型生成 AI 的硬约束提示语

可直接放在每次原型生成任务前：

> 严格依据 AI4S V1.0 基线文档和当前页面需求设计，不得自行新增一级/二级业务模块、核心对象、角色、审批链、资产类型、实验业务域或已明确删除的功能。PRD 若存在实现层面的遗漏，可仅补齐空状态、异常状态、权限状态、表单校验、搜索筛选、分页、确认、返回和已定义对象之间的必要联动；不得以“完善体验”为由扩展业务。设计前必须先确定当前角色、主任务、主对象、主操作和下一步。优先复用现有公共组件、对象和模块，外部能力优先集成而非重建。页面遵循克制、聚焦、渐进披露原则，禁止无意义统计卡片堆叠、按钮堆叠、装饰性小字和技术概念外露。

# 17. 原型审查 Checklist

## 17.1 边界

- [ ] 一级模块名称未擅自修改；
- [ ] 未新增已删除业务；
- [ ] 未重复建设 AI 中台能力；
- [ ] 未重复建设传统科研项目管理；
- [ ] 云上实验室仍只有四项核心能力。

## 17.2 对象

- [ ] Agent Session 与 Research Task 分开；
- [ ] Research Task 与 Experiment Task 分开；
- [ ] Artifact 与 Asset 分开；
- [ ] Project 与 Space 分开；
- [ ] Skill / Model 广场与科研资产分开。

## 17.3 权限

- [ ] 当前页面角色明确；
- [ ] Project / Space 数据范围明确；
- [ ] 私人会话没有被默认共享；
- [ ] 管理员管理权没有被错误解释为科研内容查看权；
- [ ] Agent 不绕过 ACL。

## 17.4 交互

- [ ] 首屏主任务明确；
- [ ] 主操作清晰；
- [ ] 不存在按钮堆叠；
- [ ] 复杂信息渐进披露；
- [ ] 状态和异常可恢复；
- [ ] Space 切换联动一致。

## 17.5 视觉结构

- [ ] 没有机械套用 Dashboard；
- [ ] Search / Agent / Asset / Management 等页面采用对应工作模式；
- [ ] 卡片字段克制；
- [ ] 表格字段与当前任务相关；
- [ ] 无无意义装饰元素和大段辅助小字。

# 18. 最终产品设计基线

AI4S V1.0 后续原型统一遵循：

> **一个 Unified Research Agent 主入口、一套 Project / Space 上下文与权限体系、一套 Research Task 执行对象、一套 Research Artifact → Research Asset 沉淀链路，以及知识、Skill、模型、工具、实验资源等可发现和可调用能力。不同角色通过导航可见性、操作权限和数据范围形成不同工作视图，而不是重复建设多套产品。**

原型重构的判断标准不是“页面是否丰富”，而是：

> **当前角色能否快速理解自己在哪里、正在处理什么对象、可以做什么、为什么可以做，以及完成后下一步进入哪里。**
