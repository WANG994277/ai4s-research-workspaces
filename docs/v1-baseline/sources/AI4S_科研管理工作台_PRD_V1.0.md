# AI4S 科研管理工作台 PRD V1.0

> 版本：V1.0  
> 产品名称：AI4S 科研平台  
> 模块名称：科研管理工作台  
> 主要角色：科研管理人员  
> 授权角色：科研项目管理人员、科研决策人员按角色叠加或授权查看部分内容  
> 数据范围：授权组织 / 授权 Project 范围  
> 设计基线：科研管理工作台用于聚合和分析 AI4S 已有科研执行对象的运行情况，服务科研管理人员“看、分析、关注、管理科研运行”；不建设新的项目全生命周期、空间 ACL、私人会话监管或独立风险业务体系。  
> 文档用途：作为原型、UI、前端、后端、数据聚合、权限与测试设计的统一开发基线。

---

# 1. 产品定位

科研管理工作台是 AI4S 面向科研管理人员的科研运行管理入口。

它不替代科研人员的 Unified Research Agent 工作台，也不替代外部科研项目管理系统。

核心目标是让科研管理人员基于授权范围内的既有对象，快速回答：

1. **当前科研项目整体运行情况怎么样？**
2. **哪些项目、课题或科研执行对象需要重点关注？**
3. **科研任务和实验执行推进到什么状态？**
4. **当前有哪些明确的失败、等待、异常或空间状态问题？**
5. **已经形成了哪些正式科研成果 / 科研资产？**
6. **需要进一步查看时，应下钻到哪个已有业务模块？**

---

# 2. 核心产品原则

## 2.1 聚合已有对象，不创造新的管理对象体系

科研管理工作台直接聚合：

```text
Project
Space
Research Task
Experiment Task
Research Asset
Instrument / Reservation（按需）
外部科研项目基础信息
```

不新建：

- Management Task；
- Management Project；
- Risk Project；
- Progress Object；
- Result Object；
- 新的科研任务模型。

“项目运行”“科研进展”“风险与异常”“科研成果”均是对已有对象的管理视图。

---

## 2.2 管理视图不改变对象归属

例如科研管理工作台看到某 Research Task：

- 不会把 Task 迁移至管理人员 Space；
- 不改变 task.owner_id；
- 不改变原 project_id / space_id；
- 不自动获得 Task 编辑权；
- 不自动获得关联私人 Agent Session 查看权。

---

## 2.3 数据范围广于普通科研人员，但仍受授权范围限制

科研管理人员默认数据范围：

> **授权组织 / 授权 Project 范围。**

不是 GLOBAL 全量科研内容。

最终访问仍受：

```text
System Role
∩ 授权组织 / Project 范围
∩ Object ACL / 内容可见性规则
```

约束。

---

## 2.4 管理科研运行，不管理平台 ACL

本模块允许科研管理人员：

- 看科研项目运行；
- 分析科研进展；
- 关注异常；
- 查看科研成果；
- 执行已明确授权的科研管理操作；
- 跳转外部科研项目管理系统。

不默认允许：

- 系统角色配置；
- Space Role 配置；
- Project / Space ACL 配置；
- 平台资源治理；
- 查看他人私人 Agent Session；
- 编辑私人 Research Artifact；
- 删除他人科研资产。

---

## 2.5 风险必须来源于可解释的既有业务状态

V1.0 不新增独立 Risk 对象和黑盒风险评分模型。

“风险与异常”只聚合可由既有对象明确判断的事项，例如：

- Research Task = FAILED；
- Research Task = WAITING_RESOURCE；
- Research Task = PAUSED；
- Research Task = WAITING_HUMAN 且需要管理关注；
- Experiment Task = EXCEPTION；
- 设备故障 / 离线导致实验执行受影响；
- Space = SUSPENDED / ARCHIVED / CLOSED 且仍存在未完成执行对象；
- 外部 Project 状态变化与 AI4S Space 状态需要人工核对；
- 外部数据源 / AI 中台映射异常影响科研执行。

如未来需要正式“风险登记、风险等级、责任人、闭环流程”，需单独明确需求，不在 V1.0 自行扩展。

# 3. 目标用户

## 3.1 科研管理人员

核心用户。

主要需求：

- 查看授权范围内科研项目；
- 掌握科研执行进度；
- 识别失败、等待和异常；
- 查看关键 Research Task；
- 查看实验执行情况；
- 查看科研成果和资产沉淀；
- 下钻到项目、课题和已有业务对象；
- 必要时进入外部科研项目管理系统。

---

## 3.2 科研项目管理人员

默认核心职责仍是 Project / Space、成员和空间权限管理。

如获得科研管理工作台授权，可以查看部分管理视图，但不因该授权改变其空间治理职责边界。

---

## 3.3 科研决策人员

可按授权查看管理工作台中的项目运行详情，作为科研决策工作台的进一步下钻入口。

直接操作权限仍以只读为主。

---

# 4. 产品边界

## 4.1 本模块负责

- 科研管理概览；
- 授权项目运行查看；
- Research Task 聚合进展；
- Experiment Task 聚合进展；
- 风险与异常聚合；
- Research Asset / 科研成果聚合；
- 项目 / 课题 / 对象下钻；
- 外部科研项目管理系统入口；
- 管理范围筛选；
- 数据更新时间 / 来源说明。

---

## 4.2 本模块不负责

- 科研项目申报；
- 立项审批；
- 经费管理；
- 合同管理；
- 中期检查流程；
- 项目验收流程；
- 完整项目归档；
- Space 创建和 ACL 配置；
- Research Agent 科研任务执行；
- 私人会话审查；
- 模型训练；
- Skill 开发；
- 科研资产内容编辑；
- 独立风险登记闭环；
- 人员绩效管理；
- 科研人员排名。

上述能力分别由外部科研项目管理系统、项目空间管理、科研工作台、AI 中台或其他既有模块承担。

# 5. 信息架构

科研管理工作台固定建议为五个二级功能：

```text
科研管理工作台
├─ 管理概览
├─ 项目运行
├─ 科研进展
├─ 风险与异常
└─ 科研成果
```

不继续向左侧导航扩展“任务中心”“实验中心”“风险中心”“成果库”等新的平级业务域。

# 6. 全局页面结构

建议：

```text
┌────────────────────────────────────────────────────────────┐
│ 科研管理工作台          管理范围 ▾    时间范围 ▾   更新时间 │
├────────────────────────────────────────────────────────────┤
│ 核心筛选：组织 / 项目 / 课题 / 状态                        │
├────────────────────────────────────────────────────────────┤
│ 当前页面主体                                               │
└────────────────────────────────────────────────────────────┘
```

科研管理工作台不强制使用科研人员的 SpaceSwitcher 作为唯一范围选择器。

原因：

- 科研人员通常处在一个 Current Space；
- 科研管理人员需要跨多个授权 Project / Space 查看运行情况。

但进入具体 Project / Space 详情后，必须仍使用同一 Project / Space 对象和权限规则。

# 7. 管理范围选择

## 7.1 数据范围来源

管理范围来自：

- 当前用户 System Role；
- 组织授权范围；
- Project 授权范围；
- 其他明确的管理数据范围。

前端不得允许用户通过输入任意 Project ID 扩大数据范围。

---

## 7.2 筛选项

建议支持：

```text
组织
Project
Topic Space
项目状态（来自外部项目系统）
Research Task 状态
Experiment Task 状态
时间范围
```

只有当前页面有业务意义的条件才展示。

---

## 7.3 默认范围

默认选择：

> 当前用户全部授权管理范围。

如果范围过大，可记忆用户上次选择，但不得突破权限边界。

# 8. 管理概览

## 8.1 页面目标

回答：

> **当前授权科研范围中，整体运行是否正常、哪里值得优先关注？**

---

## 8.2 页面结构

建议：

```text
管理范围 + 时间范围

运行概览
├─ 授权 Project 数
├─ 活跃 Research Task
├─ 等待人工 / 等待资源 / 失败任务
└─ 已形成科研资产

需要关注
├─ 失败 Research Task
├─ 等待资源 Research Task
├─ 实验异常
└─ 空间 / 外部系统异常

项目运行
└─ Project 列表 / 简明状态

科研成果
└─ 最近形成的正式 Research Asset
```

统计项控制在能支撑管理判断的必要范围，不做大面积 KPI 卡片墙。

---

# 9. 运行概览指标

所有指标必须能够落到现有对象查询。

## 9.1 授权 Project 数

口径：

```text
count(Project)
where Project ∈ current_user.authorized_management_scope
```

不等于平台 Project 总数。

---

## 9.2 活跃 Research Task

建议口径：

```text
status ∈ {
  PLANNING,
  RUNNING,
  WAITING_HUMAN,
  WAITING_RESOURCE,
  PAUSED
}
```

按当前管理范围过滤。

---

## 9.3 需要关注的 Research Task

来源：

```text
FAILED
WAITING_RESOURCE
PAUSED
```

WAITING_HUMAN 是否进入管理关注，根据：

- 是否明确需要管理角色参与；
- 是否属于关键项目 / 任务；
- 是否超过已有业务配置的关注条件。

V1.0 不自行引入未定义的 SLA。

---

## 9.4 已形成科研资产

口径：

> 当前管理范围内有权查看的正式 Research Asset。

不统计普通 Agent 回复，也不把未确认 Research Artifact 直接算作正式资产。

---

# 10. “需要关注”区

## 10.1 目标

提供科研管理人员当前最需要进一步查看的事实性异常集合。

不是审批中心，也不是新的待办系统。

---

## 10.2 事项来源

### Research Task

- FAILED；
- WAITING_RESOURCE；
- PAUSED；
- 明确需要管理人员处理的 WAITING_HUMAN。

### Experiment Task

- EXCEPTION；
- 关键实验等待确认且管理人员有查看权限。

### Instrument

- 故障；
- 离线且关联未完成 Experiment Task；
- 维护中且影响已预约资源。

### Space

- SUSPENDED；
- ARCHIVED / CLOSED 前存在未完成科研执行对象的校验提示。

### 外部集成

- Project 信息同步异常；
- AI 中台资源空间映射异常；
- 关键外部系统不可用。

---

## 10.3 卡片字段

每条至少展示：

- 事项名称；
- 对象类型；
- 所属 Project；
- 所属 Topic Space（如有）；
- 当前状态；
- 事实性原因；
- 最近更新时间；
- 主操作“查看”。

示例：

```text
页岩气储层敏感性分析
Research Task · 非常规油气前沿研究 / 页岩气储层评价课题
状态：执行失败
原因：敏感性模拟执行失败，当前计算资源不足。
最近更新：10:32

[查看任务]
```

---

## 10.4 排序

建议：

1. 执行失败；
2. 实验异常；
3. 等待资源；
4. 已暂停；
5. 其他明确异常；
6. 最近更新时间。

排序是信息组织，不定义风险等级。

# 14. 科研进展

## 14.1 页面目标

基于 Research Task 和 Experiment Task 展示科研执行进展。

不创造新的“进度填报”对象。

---

## 14.2 Research Task 视图

默认字段：

- 任务名称；
- Task 类型；
- 所属 Project；
- 所属 Space；
- Owner；
- 当前状态；
- 当前步骤；
- progress（存在真实字段时）；
- 最近更新时间；
- 是否存在异常。

---

## 14.3 状态分布

可用图表展示：

```text
规划中
运行中
等待人工
等待资源
已暂停
执行失败
已完成
已取消
```

仅作为当前管理范围的数量分布。

不得基于状态自行计算“科研效率得分”。

---

## 14.4 Task 进度

后端存在真实 progress 时展示。

如无真实百分比，只展示：

- 当前 Step；
- 已完成 Step；
- 当前状态。

禁止根据 Step 数机械推导伪精确进度。

---

## 14.5 Research Task 下钻

点击后进入只读任务详情，可查看：

- Task 基础信息；
- 当前状态；
- 执行轨迹；
- Task Step；
- 已形成 Research Artifact 摘要（按权限）；
- 已形成 Research Asset；
- 关联 Experiment Task。

默认不开放：

> 创建人私人 Agent Session 全量对话。

如果某 Session 本身已共享 / collaborative，并且当前用户有访问权限，可按正常 ACL 查看。

# 16. 风险与异常

## 16.1 页面定位

> 对当前授权科研范围中已经发生或可由既有状态明确识别的问题进行集中查看。

不是风险预测平台。

---

## 16.2 分类

建议按来源对象分组：

```text
科研任务异常
实验执行异常
科研资源异常
空间 / 集成异常
```

这是展示分类，不新增底层对象。

---

## 16.3 科研任务异常

来源：

- Research Task FAILED；
- WAITING_RESOURCE；
- PAUSED；
- 明确需科研管理人员参与的 WAITING_HUMAN。

展示：

- 任务；
- Project / Space；
- 当前 Step；
- 状态；
- 可理解原因；
- Agent 建议（如已有）；
- 更新时间。

---

## 16.4 实验执行异常

来源：

- Experiment Task EXCEPTION；
- 设备故障影响实验；
- 设备离线影响已安排实验；
- 实验结果等待确认且属于当前管理范围。

---

## 16.5 科研资源异常

只展示直接影响既有科研执行的资源状态，例如：

- Model / Tool 暂不可用导致 Task 等待；
- 软件许可证不足导致 Task 等待；
- 关键外部连接授权失效；
- AI 中台资源空间映射异常。

不建设独立资源运维后台。

---

## 16.6 空间 / 集成异常

包括：

- Project / Space 映射异常；
- 外部 Project 信息同步失败；
- Space 已暂停且仍存在需要处理的科研执行对象；
- 外部业务系统不可用。

---

## 16.7 异常详情

展示：

```text
对象
当前事实状态
影响范围
关联 Project / Space
关联任务（如有）
最近更新时间
来源系统
可下钻位置
```

不自动生成无依据的“风险等级：高/中/低”。

---

# 17. 科研成果

## 17.1 页面定位

以 Research Asset 为核心展示当前授权范围内已正式沉淀的科研成果资产。

不将普通 Agent 回复或所有 Research Artifact 作为正式成果统计。

---

## 17.2 支持资产类型

严格继承 V1.0：

```text
智能体
Skill
模型
数据集
方案模板
```

科研管理工作台只展示 AI4S 科研执行相关信息。

```text

项目负责人
项目状态
起止时间
课题关系
```

操作：

> 进入科研项目管理系统

用于处理：

- 项目主数据；
- 申报；
- 立项；
- 经费；
- 合同；
- 检查；
- 验收等。

---

# 19. 与项目空间管理的关系

科研管理工作台：

> 看科研运行。

项目空间管理：

> 管 Project / Space / Membership / Space Role / Permission。

科研管理人员默认不能在管理工作台直接：

- 邀请成员；
- 修改 Space Role；
- 修改 ACL；
- 关闭 Space。

如用户叠加“科研项目管理人员”角色，则通过对应模块进入管理。

---

# 20. 与科研工作台的关系

科研工作台面向科研人员执行研究。

科研管理工作台面向科研管理人员查看授权范围的执行态势。

二者共同使用：

```text
Research Task
Task Step
Task Execution
Human Decision
Research Artifact
Research Asset
```

但科研管理工作台不能因为聚合 Task 就自动获得私人 Session 内容。

---

# 21. 与科研决策工作台的关系

科研管理工作台：

- 粒度更细；
- 面向日常科研运行；
- 更重项目、任务和异常下钻。

科研决策工作台：

- 范围更广；
- 更重跨项目态势、重大项目、成果和资源；
- 操作更少。

决策工作台可以下钻到科研管理工作台的授权项目详情。

# 27. 权限模型


## 27.1 可查看

# 28. 角色叠加

如果用户同时是：

```text
科研人员 + 科研管理人员
```

则：

- 一级导航取权限并集；
- 科研工作台仍按其科研人员身份使用；
- 科研管理工作台按授权管理范围使用；
- 不能因为管理角色而绕过私人对象 ACL。

如果同时是：

```text
科研项目管理人员 + 科研管理人员
```

则可分别进入：

- 项目空间管理；
- 科研管理工作台。

职责和操作入口仍保持分离。

# 36. 核心验收标准

## 36.1 产品边界

- [ ] 不建设科研项目申报 / 经费 / 合同 / 验收；
- [ ] 不建设 Space ACL 管理；
- [ ] 不建设新的风险对象体系；
- [ ] 不建设私人会话监管；
- [ ] 不重复建设科研工作台。

## 36.2 管理概览

- [ ] 可以选择授权管理范围；
- [ ] 可以查看 Project、Research Task、异常和 Research Asset 聚合信息；
- [ ] 指标均可追溯到已有对象；
- [ ] 显示数据来源和更新时间。

## 36.3 项目运行

- [ ] 项目主数据来自外部科研项目管理系统；
- [ ] AI4S 内只展示科研执行和空间关联；
- [ ] 可下钻 Project / Space / Task / Asset；
- [ ] 不允许在 AI4S 修改外部项目主数据。

## 36.4 科研进展

- [ ] Research Task 按既有状态聚合；
- [ ] Experiment Task 与 Research Task 分开；
- [ ] 无真实 progress 时不伪造百分比；
- [ ] 管理人员默认不查看私人 Agent Session。

## 36.5 风险与异常

- [ ] 所有事项来自已有对象真实状态；
- [ ] 不自动生成黑盒风险分值；
- [ ] 可解释异常来源和影响对象；
- [ ] 可下钻原业务模块。

## 36.6 科研成果

- [ ] 以正式 Research Asset 为主；
- [ ] 不把普通 Agent 回复作为正式成果；
- [ ] 资产类型继承 V1.0；
- [ ] 查看、分享、发布等继续受科研资产权限控制。

## 36.7 权限

- [ ] 科研管理人员只查看授权组织 / Project 范围；
- [ ] 管理权不等于私人科研内容查看权；
- [ ] 角色叠加后仍执行对象 ACL；
- [ ] 非授权 Project 不通过搜索、统计或下钻泄露。

# 37. 最终产品基线

科研管理工作台最终定义为：

> **AI4S 面向科研管理人员的科研运行管理入口，在授权组织和 Project 范围内聚合 Project、Space、Research Task、Experiment Task、Research Asset 及相关资源状态，帮助管理人员查看项目运行、科研进展、明确异常和科研成果，并通过对象下钻进入既有业务模块；本模块不重新建设科研项目全生命周期、空间权限后台、私人科研内容监管或独立风险管理体系。**

核心链路统一为：

```text
管理范围
    ↓
Project / Space 运行态势
    ↓
Research Task / Experiment Task 进展
    ↓
失败 / 等待 / 异常等明确关注事项
    ↓
Research Asset 科研成果
    ↓
下钻既有模块 / 外部科研项目管理系统
```
