# AI4S 科研决策工作台 / 科研驾驶舱 PRD V1.0

> 版本：V1.0  
> 产品名称：AI4S 科研平台  
> 模块名称：科研决策工作台 / 科研驾驶舱  
> 主要角色：科研决策人员  
> 授权角色：科研管理人员按角色叠加或授权查看部分决策视图  
> 数据范围：按授权组织 / 授权 Project 范围，可覆盖多个项目与科研空间  
> 设计基线：科研决策人员“数据范围更广，但直接操作权限更少”；驾驶舱只对 AI4S 已有 Project、Space、科研执行、科研资产、科研资源等对象进行跨项目汇总和下钻，不重新建设科研项目管理、资源调度、人员绩效或自动决策体系。  
> 文档用途：作为原型、UI、前端、后端、指标聚合、权限和测试设计的统一开发基线。

---

# 1. 产品定位

科研决策工作台 / 科研驾驶舱是 AI4S 面向科研决策人员的跨项目科研态势查看与决策信息入口。

其核心价值不是替代人的科研决策，也不是提供一个“大屏展示页面”，而是基于授权科研范围，将分散在 AI4S 各模块中的可追溯数据组织成可理解、可下钻的决策视图。

核心回答：

1. **当前整体科研运行态势如何？**
2. **哪些重大项目值得重点关注？**
3. **当前有哪些明确的科研执行风险与异常？**
4. **形成了哪些正式科研成果和可复用资产？**
5. **当前有哪些可用科研资源，分布和使用状态如何？**
6. **需要进一步判断时，能够下钻到哪些事实依据？**

---

# 2. 核心产品原则

## 2.1 数据范围更广，但操作权限更少

科研决策人员可按授权：

- 跨 Project 查看；
- 查看科研态势；
- 查看重大项目；
- 查看科研成果；
- 查看科研资源；
- 下钻管理视图和公开 / 授权业务详情。

默认不允许：

- 编辑项目日常数据；
- 配置 Space 成员；
- 修改 Space Role；
- 修改 ACL；
- 删除科研资产；
- 修改模型 / Skill；
- 调整平台配置；
- 查看私人 Agent Session；
- 代替科研人员做 Human Decision。

---

## 2.2 决策工作台只汇总已有对象

底层依赖：

```text
Project
Space
Research Task
Experiment Task
Research Asset
Skill
Model
Dataset
Tool
Software
Instrument
Membership / User / professional_tags（仅授权聚合）
```

驾驶舱中的：

```text
科研态势
重大项目
风险与异常
科研成果
科研资源
```

均为这些对象的决策视图，不建立新的业务主对象。

---

## 2.3 不做“黑盒综合评分”

V1.0 不默认提供：

- 项目综合得分；
- 科研人员绩效得分；
- 项目健康度 0～100；
- AI 自动立项建议；
- AI 自动终止项目建议；
- 黑盒科研价值排名；
- 黑盒人员排名。

如展示“重点关注”，必须给出事实依据，例如：

> 2 个 Research Task 执行失败，1 个实验任务异常。

而不是：

> 项目风险评分 87。

---

## 2.4 “重大项目”必须来自明确业务来源

重大项目可来自：

- 外部科研项目管理系统中的明确项目属性；
- 已有管理制度中的项目分类；
- 当前用户授权范围内的明确配置。

不得根据模型自动推断“重大项目”后直接作为正式业务结论。

如果目前没有“重大项目”字段，则原型可使用“重点项目（业务配置）”作为待配置展示，不自行生成名单。

---

## 2.5 决策必须可追溯

所有关键数字、趋势和异常都应能够下钻至：

- Project；
- Space；
- Research Task；
- Experiment Task；
- Research Asset；
- 资源对象；
- 来源系统；
- 更新时间。

避免只展示无法解释来源的大数字。

# 3. 目标用户

## 3.1 科研决策人员

主要需求：

- 查看授权范围整体科研态势；
- 跨项目了解科研运行；
- 查看重点 / 重大项目；
- 查看科研任务和实验异常；

根据授权可查看部分决策视图，但其主要工作入口仍为科研管理工作台。

科研管理人员更关注日常运行；科研决策人员更关注跨项目整体态势。

```text

- 战略任务管理；

## 7.2 选择器

建议支持：

- 组织；
- 项目类别（仅有真实字段时）；
- Project；
- 学科；
- 时间范围。

Topic Space 一般作为下钻筛选，不需要在驾驶舱首页成为主筛选项。

## 7.3 学科口径

学科沿用平台已有：

通用

```

# 8. 科研态势

## 8.1 页面目标

回答：

> **当前授权范围的科研活动、执行、成果和资源处于什么整体状态？**

---

## 8.2 态势摘要

建议控制在 4～6 个真正有决策意义的指标：

- 授权 Project 数；
- 活跃 Research Task 数；
- 当前存在明确异常的 Project 数；
- 已形成正式 Research Asset 数；
- 当前可用科研模型 / Skill / 工具资源数（按需）；
- 可共享仪器设备数（按需）。

指标必须明确统计口径。

---

## 8.3 授权 Project 数

```text
count(Project)
where Project ∈ current_decision_scope
```

---

## 8.4 活跃 Research Task 数

建议：

```text
status ∈ {
  PLANNING,
  RUNNING,
  WAITING_HUMAN,
  WAITING_RESOURCE,
  PAUSED
}
```

---

## 8.5 存在明确异常的 Project 数

项目被计入的条件可包括任一：

- 至少一个 Research Task = FAILED；
- 至少一个 Experiment Task = EXCEPTION；
- 存在直接影响科研执行的关键资源异常；
- 存在 Project / Space / 外部系统映射异常。

这是事实聚合，不定义新的项目风险状态。

---

## 8.6 Research Asset 数

仅统计当前决策范围内有权查看的正式 Research Asset。

不把 Research Artifact 和普通回答自动纳入。

---

# 9. 科研态势趋势

可展示：

## 9.1 Research Task 活动趋势

按周 / 月聚合：

- 新建持续科研任务；
- 完成任务；
- 失败任务。

仅用于观察活动变化，不等于科研绩效。

---

## 9.2 科研资产沉淀趋势

按时间展示新增 Research Asset 数。

支持按：

- Asset Type；
- Project；
- 学科；

查看分布。

---

## 9.3 实验执行趋势

在云上实验室数据完整时可展示：

- Experiment Task 新增 / 完成数量；
- 异常数量；
- 共享设备使用情况。

指标必须标明数据源。

---

# 10. 项目结构分布

可按以下维度进行事实性分布：

- 组织；
- 学科；
- Project 状态；
- 项目来源；
- 课题数量区间（按需）。

禁止将“项目数量多”解释为“科研能力强”。

---

# 11. 重大项目

## 11.1 页面定位

集中查看业务上已明确标识为重大 / 重点的 Project。

---

## 11.2 数据来源

优先级：

```text
外部科研项目管理系统明确属性
→ 业务配置
→ 无数据则不展示“重大项目”正式标签
```

不使用 AI 自动推断作为正式项目属性。

---

## 11.3 项目卡片 / 列表字段

建议：

- 项目名称；
- 项目编号；
- 牵头单位；
- 项目负责人；
- 项目状态；
- 起止时间；
- Topic Space 数；
- 活跃 Research Task；
- 明确异常事项；
- 正式 Research Asset；
- 最近科研活动时间。

---

## 11.4 重大项目详情

采用决策只读结构：

```text
项目概况
科研执行态势
主要课题
当前明确异常
科研成果
科研资源使用概况
数据来源
```

可进一步：

> 查看科研管理详情

进入科研管理工作台对应 Project。

---

# 12. 项目执行态势

重大项目详情可展示 Research Task 状态分布：

```text
运行中
等待人工
等待资源
暂停
失败
完成
```

不把状态分布合成为黑盒“进度指数”。

如 Project 本身在外部项目管理系统有正式里程碑或进度字段，可明确标注外部来源后展示，但本模块不新建该字段。

# 13. 风险与异常

## 13.1 定位

从决策视角聚合跨项目的明确异常事实。

与科研管理工作台共享底层异常来源，但驾驶舱强调：

- 影响 Project 数；
- 类型分布；
- 趋势；
- 重点项目中的异常；
- 下钻依据。

---

## 13.2 异常来源

严格基于已有状态：

### Research Task

- FAILED；
- WAITING_RESOURCE；
- PAUSED；
- 明确需管理 / 决策关注的 WAITING_HUMAN。

### Experiment Task

- EXCEPTION。

### Instrument / Resource

- 故障 / 离线影响实验；
- 模型 / 工具 / 软件 / 外部连接不可用并影响 Task；
- 关键资源等待。

### Space / Integration

- Space 状态异常；
- Project 同步异常；
- AI 中台资源空间映射异常；
- 关键外部系统不可用。

---

## 13.3 驾驶舱展示

建议：

```text
异常 Project 数
异常事项总数
按异常来源分布
按 Project 分布
近期变化趋势
重点项目异常列表
```

---

## 13.4 不提供默认风险打分

不出现：

```text
风险 92 分
健康度 61 分
项目红黄绿综合评级
```

除非未来有正式、可审计的业务规则和数据基线。

当前可使用基于事实状态的标签：

```text
存在执行失败
存在实验异常
存在资源等待
存在同步异常
```

---

# 14. 异常下钻

点击任意异常指标可进入：

```text
Project
→ 对应 Research Task / Experiment Task / Resource / Space
→ 原业务详情
```

科研决策人员默认只读。

需要业务处理时，可由具备对应角色的人员在原模块完成。

# 15. 科研成果

## 15.1 页面定位

从跨项目视角查看正式科研资产沉淀和发布情况。

---

## 15.2 底层对象

核心使用：

> Research Asset

正式资产类型沿用 V1.0：

```text
智能体
Skill
模型
数据集
方案模板
```

---

## 15.3 成果摘要

建议展示：

- 正式资产总量；
- 本期新增资产；
- 已共享资产；
- 已发布资产；
- 按 Asset Type 分布；
- 按 Project / 学科分布。

只统计当前决策人员有权查看的范围。

---

## 15.4 成果趋势

支持：

```text
月度 / 季度新增 Research Asset
发布资产趋势
共享资产趋势
```

不以资产数量直接评价项目科研质量。

---

## 15.5 代表性成果

如果需要展示“重点 / 代表性成果”，其选择必须来自：

- 明确的业务标识；
- 已发布状态；
- 已有管理配置；

而不是由 AI 在无规则情况下自动排行。

无对应字段时，V1.0 可仅展示“最近发布 / 最近更新”的成果。

---

## 15.6 成果详情

点击后进入 Research Asset 只读详情。

展示：

- 基础信息；
- Asset Type；
- Project / Space；
- Owner；
- 版本；
- 来源；
- 发布状态；
- 共享状态；
- 来源 Research Task（有权时）；
- 可追溯关系。

不默认提供编辑、删除操作。

# 16. 科研资源

## 16.1 页面定位

从决策层了解平台和授权科研范围内可用于科研的资源构成与可用状态。

科研资源不是一个新的统一业务对象表，而是多个现有资源对象的聚合视图。

---

## 16.2 资源类型

可聚合：

```text
Skill
Model
Dataset
Tool
Software
Instrument
```

Agent 可在需要时作为可调用资源统计，但需注意 Agent 资产 / 发布资源的对象关系。

MCP / Connector 是技术接入形式，不作为决策主分类。

---

## 16.3 资源概览

建议展示：

- 已发布 Skill 数；
- 已发布 Model 数；
- 可访问 Dataset 数；
- 可用科研工具 / 软件数；
- 可共享仪器数；
- 暂不可用资源数。

统计范围与用户授权一致。

---

## 16.4 资源分布

可按：

- 学科；
- 资源类型；
- 所属 Project / 公共范围；
- 可用状态；

分析。

不得根据资源数量自动推断科研竞争力。

---

## 16.5 资源状态

前台统一使用已有业务状态：

```text
可用
需要授权
权限受限
维护中
暂不可用
已下架
```

仪器使用自身运行 / 共享状态。

---

# 17. 科研人员 / 专业结构的处理原则

V1.0 不新增“人才管理”一级功能。

如果科研决策场景确需了解团队结构，可仅基于已有：

```text
User
Membership
professional_tags
Project / Space Membership
```

做授权范围内的结构性统计，例如：

- 项目成员数量；
- 学科标签分布；
- 课题成员分布。

禁止扩展：

- 人才画像评分；
- 科研人员能力排名；
- 绩效排名；
- 薪酬 / 人事档案；
- 自动选人推荐结论。

---

# 18. 科研态势摘要生成

可提供轻量 AI 摘要，但必须严格基于当前可见数据。

示例：

```text
当前授权范围包含 12 个科研项目，其中 3 个项目存在执行异常。
异常主要来自 2 个 Research Task 执行失败和 1 个 Experiment Task 异常。
本季度新增正式科研资产 18 项，其中模型 4 项、数据集 6 项。
```

要求：

- 每个关键数字可点击下钻；
- 明确时间范围；
- 不加入未经数据支持的因果判断；
- 不把描述性摘要写成领导决策建议。

---

# 19. 趋势对比

## 19.1 支持范围

可以比较：

- 不同时间段；
- 不同组织；
- 不同 Project；
- 不同学科；
- 不同资源类型。

## 19.2 展示规则

仅展示事实差异：

```text
数量
占比
状态分布
趋势变化
```

不生成：

> A 项目优于 B 项目

这类无明确业务评价标准的结论。

---

# 20. 与科研管理工作台的关系

科研决策工作台负责：

> 跨项目宏观态势。

科研管理工作台负责：

> 授权项目日常科研运行查看与异常下钻。

典型链路：

```text
科研驾驶舱
→ 点击存在异常的 Project
→ 科研管理工作台 Project 详情
→ Research Task / Experiment Task
→ 原业务详情
```

沿途权限不放大。

---

# 21. 与外部科研项目管理系统的关系

项目主数据和项目管理流程仍来自外部科研项目管理系统。

驾驶舱可以展示：

- Project 名称；
- 编号；
- 项目状态；
- 负责人；
- 起止时间；
- 重大项目属性（如有）；

并明确来源。

如需查看：

- 经费；
- 合同；
- 立项；
- 验收；
- 正式项目计划；

应进入外部科研项目管理系统，不在 AI4S 中虚构数据。

---

# 22. 与科研资产的关系

驾驶舱只读聚合科研资产。

资产的：

- 版本管理；
- 分享；
- 发布申请；
- 编辑；
- 归档；

仍在科研资产模块按权限完成。

决策人员查看资产不自动获得这些写权限。

---

# 23. 与科研资源广场的关系

驾驶舱展示资源统计和分布。

具体发现和使用仍进入：

```text

科研模型
科研工具箱
云上实验室
科研资产
```

不在驾驶舱内复制完整资源卡片详情和调用流程。

# 28. 权限模型

统一遵循：

```text
System Role = 科研决策人员（或叠加授权）
∩ 决策数据范围
∩ Project / Space 可见范围
∩ Object ACL / 内容可见性规则
```

原则：

> **数据范围广 ≠ 操作权限大。**

---

# 29. 关键权限规则

## 29.1 跨 Project 查看

仅限授权范围。

## 29.2 Project 日常编辑

默认禁止。

## 29.3 Space 成员配置

默认禁止。

## 29.4 Asset 删除

默认禁止。

## 29.5 私人 Agent Session

默认不可查看。

## 29.6 Research Task

可查看授权范围的业务状态、执行轨迹和必要对象关系；私人交互内容继续按 Session ACL 判断。

# 30. 角色叠加

如用户同时为：

```text
科研人员 + 科研决策人员
```

则可同时拥有：

- 科研工作台；
- 科研决策工作台。

但两种角色的数据范围和交互上下文分开计算。

如同时为：

```text
科研管理人员 + 科研决策人员
```

则：

- 决策驾驶舱用于整体态势；
- 科研管理工作台用于项目级下钻。

# 31. 可视化规范

# 39. 核心验收标准

## 39.1 角色边界

- [ ] 科研决策人员以查看和分析为主；
- [ ] 不提供项目日常编辑；
- [ ] 不提供 Space 成员 / 权限配置；
- [ ] 不提供 Asset 删除；
- [ ] 不默认查看私人 Agent Session。

## 39.2 科研态势

- [ ] 可跨授权 Project 聚合；
- [ ] 核心指标均来自已有对象；
- [ ] 指标有口径、时间范围和数据来源；
- [ ] 关键数字可下钻。

## 39.3 重大项目

- [ ] 重大 / 重点属性来源明确；
- [ ] 无业务字段时不由 AI 自行判定；
- [ ] 可查看 Project 运行、异常、成果；
- [ ] 可下钻科研管理工作台。

## 39.4 风险与异常

- [ ] 来自 Research Task / Experiment Task / Resource / Space / Integration 真实状态；
- [ ] 不默认生成风险评分；
- [ ] 显示事实原因；
- [ ] 可下钻原始对象。

## 39.5 科研成果

- [ ] 以 Research Asset 为核心；
- [ ] Asset Type 不越过 V1.0 基线；
- [ ] 分享 / 发布 / 编辑不在驾驶舱重复建设；
- [ ] 不以资产数量评价科研质量。

## 39.6 科研资源

- [ ] 聚合 Skill / Model / Dataset / Tool / Software / Instrument；
- [ ] MCP / Connector 不作为科研决策一级资源分类；
- [ ] 不新建重复资源对象；
- [ ] 可下钻原资源模块。

## 39.7 数据与权限

- [ ] 数据范围来自授权组织 / Project；
- [ ] 非授权数据不进入统计结果；
- [ ] 外部数据源异常可见；
- [ ] 角色叠加不绕过 Object ACL；
- [ ] 数据范围广不等于操作权限大。

---

# 40. 最终产品基线

科研决策工作台 / 科研驾驶舱最终定义为：

> **AI4S 面向科研决策人员的跨项目科研态势查看与决策信息入口，在授权范围内对 Project、Research Task、Experiment Task、Research Asset 以及 Skill、Model、Dataset、Tool、Software、Instrument 等既有对象进行汇总分析，重点呈现整体科研态势、重大项目、明确风险与异常、科研成果和科研资源，并支持逐级下钻至科研管理工作台和原始业务对象；驾驶舱本身以只读分析为主，不重新建设项目管理、权限管理、人员绩效、资源调度或自动科研决策体系。**

核心链路统一为：

```text
授权决策范围
    ↓
科研总体态势
    ↓
重大 / 重点 Project
    ↓
明确风险与异常
    ↓
Research Asset 科研成果
    ↓
科研资源结构与可用状态
    ↓
Project / Task / Asset / Resource 事实下钻
```
