# ADR：模块切换性能优化

## 需求

科研平台在开发环境首次切换模块时需要等待数秒，影响原型演示和日常验证。目标是在保留按模块分包的前提下，让常用模块切换稳定进入亚秒级。

## 候选方案

1. 将所有页面改为静态导入：切换最快，但首屏包体和解析成本过高。
2. 仅依赖 Next.js `Link` 预取：生产环境有效，但无法提前加载嵌套的 `next/dynamic` 页面分包，开发环境也不会完整预取。
3. 使用 Turbopack，并对有权限的导航路由和动态模块执行悬停预取与空闲时顺序预热。

## 决策

选择方案 3：开发命令使用 Next.js 16 的 Turbopack；导航在悬停和键盘聚焦时立即预热目标，同时在页面空闲后顺序预热有权限的模块。共享分包通过单例 Promise 去重。开发环境额外发起同源 GET 以提前完成路由编译。

Tailwind 只扫描 `src/`，避免本地构建缓存和历史项目副本被识别为样式类并拖慢或破坏 CSS 编译。

## 权衡与替换路径

- 初始页面稳定后会产生后台网络和解析工作，但按顺序执行，避免同时加载全部分包。
- 只预热当前用户有权限的导航项。
- 如果后续页面拆分后单包足够小，可减少空闲预热范围，仅保留悬停预取。
