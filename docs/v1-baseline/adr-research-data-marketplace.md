# ADR：科研数据广场的对象复用与页面边界

## 需求

在左侧“科研广场”中新增科研数据集的发现和使用入口，界面参考科研技能广场，同时保持科研资产、数据处理与知识中心的边界清晰。

## 候选方案

1. 新建独立 Dataset 存储和数据流程：页面独立，但会与 Research Asset 重复对象、版本、权限和发布状态。
2. 将广场放入科研资产的一个页签：复用简单，但将“发现已发布资源”与“管理我的/项目资产”混合。
3. 建立独立广场视图，复用 `Research Asset(type=数据集)`：同一对象在不同生命周期与产品视图中呈现。

## 选择

选择方案 3。`/datasets` 仅展示 `type=数据集` 、`publishStatus=已发布` 且未归档的对象，并继续使用 `canRead/canUse` 与 Space/Project/Asset ACL 策略。

- 广场负责：搜索、筛选、预览、评估、收藏、申请权限、加入 Research Agent/当前研究。
- 科研资产负责：所有权、共享、版本管理、发布审核、归档。
- 数据处理工作流负责：清洗、转换、质量检查与产出新版本。
- AI 中台负责：真实数据集创建与外部对象映射。

## 复用与购买决策

- 继续使用 Next.js 16、React 19、Lucide、Radix Dialog 和已有本地状态层，不引入新 UI/表格/搜索依赖。
- 原型规模只有少量示例数据，不需要虚拟列表、独立搜索服务或对象存储。
- 未来对接生产系统时，用 API 替换本地数组与 localStorage，保留 `DatasetMetadata`、路由查询参数和权限语义。对象文件可交由企业对象存储，大规模预览可换成专用 Dataset Viewer/分片 API。

## 权衡

- 优点：避免重复数据，保持发布、版本和权限可追溯；可直接复用现有 ContextActions 与迁移逻辑。
- 代价：通用 Asset 需增加可选的 `dataset` 元数据扩展；真实数据的大文件、审批、许可接受和服务端授权仍需后端能力。
