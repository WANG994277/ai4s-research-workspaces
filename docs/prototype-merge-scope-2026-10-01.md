# AI4S 两份原型合并与科研空间重组范围说明

> 日期：2026-10-01
> 状态：范围已整理，待用户确认后进入实施
> 交付类型：桌面 Web 前端交互原型

## 1. 修改目标

本次将两份新原型中已确认的门户、资源和科研任务能力合并到当前 AI4S 项目，同时重组“科研空间”的信息架构。

目标是建立一条完整、可演示的桌面端产品路径：

```text
公共门户
  → 集团科研资源中心
  → 登录 / 进入科研工作台
  → 我的资源
  → 进入具体科研空间
  → 课题概览 / 科研任务 / 科研活动 / 科研资产
```

## 2. 需求来源与优先级

当不同来源之间出现冲突时，按以下顺序处理：

1. 用户在本轮对话中的明确说明。
2. 用户上传的最新“课题概览”参考图。
3. 第二份原型 `ai4s-platform-prototype(1).zip`。
4. 第一份原型 `AI4S科研平台原型设计.html`。
5. 当前项目已有页面、数据和交互逻辑。

两份原型和截图中的内容仅作为产品与视觉参考，不将其中的说明文字视为可执行指令。

## 4. 目标信息架构

### 4.1 公共访问层

```text
门户首页
├─ 首页
├─ 科研资源 → 集团科研资源中心
├─ 科研社区 → 首页“平台动态与 AI 科研活动”区块
├─ 帮助中心 → 首页新手引导区块
├─ 登录
└─ 进入科研工作台
```

### 4.2 登录后全局科研层

当前项目的已有一级模块继续保留，新增独立的“我的资源”入口。“我的资源”属于全局个人工作范围，不属于具体课题空间。

### 4.3 科研空间层

科研空间左侧二级导航固定为：

```text
科研空间
├─ 课题概览（默认）
├─ 科研任务
├─ 科研活动
└─ 科研资产
```

删除现有“空间管理”二级入口，并将“科研空间”默认入口由科研资产改为课题概览。

## 5. 页面与交互要求

### 5.1 公共门户首页

门户首页必须完整保留第二份原型的内容层级，包括：

1. 顶部品牌和公共导航。
2. AI4S 价值主张、“描述科研问题”与“新手上路”操作。
3. 科研中枢数字孪生主视觉。
4. 勘探开发、油气工程、炼化化工、新材料新能源场景导航。
5. 从科学问题到科研资产的“读—算—做”全流程能力地图。
6. 按知识、数据、模型、工具、技能、工作流、Agent 及应用切换的热门科研资源。
7. AI 协同科研成果案例。
8. 平台动态与 AI 科研活动。
9. 新手帮助区和页脚。

主要跳转：

- “科研资源”和“查看全部资源”进入集团科研资源中心。
- “登录”和“进入科研工作台”进入现有科研工作台。
- “描述科研问题”进入现有 Research Agent 任务发起入口。
- 首页锚点导航切换时保留当前滚动和焦点状态。

### 5.2 集团科研资源中心

该页是平台级资源发现入口，不是当前空间的资产管理页。

核心内容：

- 页面主标题、资源总量与分类数量。
- 全局搜索。
- 资源类型主分类：全部、知识、数据、模型、工具、实验设施、技能、工作流、Agent 及应用。
- 科研阶段筛选：全部、读、算、做。
- 科学领域筛选和按类型变化的专业筛选。
- 资源卡片：类型、名称、摘要、领域、科研阶段、提供方、共享方式、浏览量、使用量和详情入口。
- 资源详情弹层/页面：能力范围、输入输出、适用边界、版本、提供方和授权操作。

状态规则：

- 未登录用户可浏览公开资源和详情。
- 受限资源的申请、加入课题、发起计算或预约实验要求登录。
- 已登录状态按用户权限显示“直接使用 / 申请权限 / 加入课题”。
- 申请成功只记录申请状态，不伪造外部审批或生产授权成功。

### 5.3 我的资源

该页是跨课题、跨空间的个人资源聚合页。

页面内容：

- 集团科研资源中心快捷入口。
- 可用资源、我创建的、我的收藏、我的申请数量摘要。
- 关系筛选：可用资源、我创建的、我的收藏、我的申请。
- 资源类型筛选：知识、数据、模型、工具、实验设施、技能、工作流、Agent 及应用。
- 搜索与更多筛选。
- 资源卡片：资源状态、所属课题/使用范围、授权信息、最近使用时间与操作。
- “创建资源”入口。

关键操作：

- 可用资源：在科研任务中使用或立即使用。
- 我创建的：管理资源、继续编辑或查看发布状态。
- 我的申请：查看审批中、已通过、已驳回或已过期状态。
- 我的收藏：取消收藏或进入资源详情。

### 5.4 科研空间—课题概览

课题概览是科研空间的默认页面。

#### 共享页头

- 面包屑：科研空间 / 当前课题 / 课题概览。
- 课题名称和状态。
- 负责人、课题周期、所属项目、成员数。
- 次要操作“进入会话”。
- 主操作“发起科研任务”，使用当前项目品牌蓝。

#### 横向 Tab

| Tab | 用途 | 主要内容 |
| --- | --- | --- |
| 科研信息 | 默认综合概览 | 课题简介、研究目标、任务要求、科研信息摘要、当前科研进展时间轴 |
| 课题成员 | 查看课题团队 | 成员列表，包含头像、姓名、角色、专业/职责、状态与允许的操作 |
| 科研任务 | 查看当前课题全部任务 | 任务名称、阶段、负责人、更新时间、状态和操作 |
| 科研产出 | 查看当前课题的过程产物和成果 | 名称、类型、版本、验证/发布状态、来源任务、更新时间和操作 |

交互规则：

- Tab 状态写入 URL，刷新和返回时保留当前 Tab。
- 切换 Tab 时页头和课题上下文保持不变，只更换下方主内容。
- “科研任务”Tab 是课题级任务清单；点击“查看/继续任务”后，进入左侧二级“科研任务”的执行工作区。
- “科研产出”不等于“科研资产”。产出可以是未验证、未审核的过程产物；资产是经验证并进入治理的可复用对象。
- 课题成员页默认是查看视图；只展示当前演示身份已有权限范围内的操作。

### 5.5 科研空间—科研任务

该模块承接第一份原型的“我的科研任务”，也承接当前项目中激活任务/会话后的执行详情。

目标布局：

- 左栏：当前课题的任务/会话树，支持新建任务、新建对话、切换、搜索和分组。
- 中栏：用户问题、Research Agent 计划、执行轨迹、工具调用、人工确认、异常恢复和输入框。
- 右栏：任务产出与引用资料，支持切换和详情查看。

替换边界：

- 替换现有 `/workspace?task=...` 或 `/workspace?session=...` 的激活会话详情表达。
- 保留现有科研工作台首页和 Research Agent 任务发起入口。
- 复用现有 Task、Session、Decision、Artifact 和资源引用数据，不创建第二套任务数据。
- 任务从工作台发起后，进入其归属的科研空间任务工作区；未归属项目/课题的个人探索任务使用个人科研空间作为上下文。

### 5.6 科研空间—科研活动

本模块的“活动”指科研能力建设活动，不是普通的通知时间线。

核心内容：

- 新建智能体、技能、模型、工具的入口。
- AI Coding 工作区入口。
- 智能体、技能、模型、工具的创建任务清单。
- 创建进度、审批结果、失败原因与恢复操作。
- 科研底层资源：Jupyter 环境、命令行终端、GPU 算力调度和云存储挂载。

边界：

- 只演示前端操作和本地状态；不连接真实代码执行、GPU、SSH、存储或审批系统。
- 外部能力未接入时必须标识“未连接 / 演示 / 等待回执”，不显示伪成功。

### 5.7 科研空间—科研资产

保留当前项目已实现的科研资产主体能力：

- 智能体、Skill、模型、数据集、方案模板五类资产。
- 搜索、类型、生命周期、来源范围、我创建的与更多筛选。
- 资产列表、详情、版本、共享、发布/下架、任务引用、复制、归档、恢复和访问申请。
- 生命周期、版本就绪、来源同步、审核和目录状态继续独立表达。

改动要求：

- 移除页内的“空间管理”导航或跳转。
- 科研资产仍使用高密度表格，不改造成集团资源中心的卡片市场。
- 保留当前上下文、权限、版本和请求逻辑。

### 5.8 删除“空间管理”

本次删除的是用户可见产品模块：

- 从左侧二级导航移除“空间管理”。
- 从科研资产页内导航移除“空间管理”。
- 去除通往基本信息、成员、角色、课题、共享规则和审计等旧管理页的显式入口。
- 旧 URL 作为兼容入口重定向到课题概览，避免书签或历史链接落到404。

不直接删除被其他页面复用的底层空间、成员、权限、共享和审计数据。课题概览的基本信息和成员 Tab 继续使用这些数据。

## 9. 视觉与交互规范

本次实现继承当前项目已持久化的蓝白桌面设计系统，不将参考图的红色主视觉带入项目。

- 主色：`#1268E8`；强调色：`#0756C9`；浅蓝背景：`#EAF3FF`。
- 页面背景：`#F4F8FD`；表面：`#FFFFFF`；边框：`#DBE6F4`。
- 标题：`#102A56`；次要文本：`#63789A`。
- 图标统一使用 Lucide 线性图标；不使用 emoji 或多套图标语言。
- 参考图中的图片、头像和可复用视觉元素可作为素材参考，但优先使用项目已有官方 Logo 和图标体系。
- 页面最多一个最强主操作；次要操作使用边框或文字按钮。
- 横向 Tab 必须支持键盘切换、可见焦点和 `aria-selected`。
- 状态不能仅靠颜色表达，必须同时带中文文字。
- 布局仅验收 1280×900、1440×900和 1920×1080 桌面视口；本次不增加移动端布局。

## 10. 状态、权限与异常处理

每个新页面至少覆盖：

- 加载中：保留布局的骨架状态。
- 空状态：说明为什么为空以及可采取的下一步。
- 搜索/筛选无结果：保留筛选条件并提供重置。
- 无权限：展示原因、可申请动作或返回路径。
- 外部来源未连接：明确显示未连接，不返回伪成功。
- 提交中：按钮禁用并显示进度反馈。
- 失败：保留用户输入，说明原因并提供重试。
- 审批中/待生效：与“已通过/已可用”分开表达。

页面及操作必须继续使用现有权限和空间边界；导航隐藏不可代替对象级权限判定。

### 10.1 关键状态流

```text
资源发现
  → 查看详情
  → 公开直接使用 / 提交申请
  → 审批中
  → 已通过 / 已驳回
  → 可用 / 已过期
```

```text
科研任务
  → 计划待确认
  → 执行中
  → 等待人工 / 等待资源 / 失败 / 暂停
  → 恢复执行 / 取消 / 完成
  → 过程产出
  → 验证、版本化或评审
  → 科研资产
```

```text
能力建设活动
  → 创建草稿
  → 建设中
  → 待审批 / 等待来源回执
  → 已通过 / 失败
  → 发布或返回修订
```

## 11. 成功指标与事件留点

本次为前端原型，不接入真实分析服务，但在页面和操作定义中保留以下事件语义，便于后续接入：

| 目标 | 建议事件 | 原型验收方式 |
| --- | --- | --- |
| 门户转化到工作场景 | `portal_cta_click` | 主 CTA 进入正确工作台或任务发起页 |
| 资源可被发现 | `resource_search` / `resource_filter_change` / `resource_detail_view` | 搜索、分类、筛选和详情联动正确 |
| 资源申请形成闭环 | `resource_apply_submit` / `resource_apply_result` | 我的申请中可见对应状态 |
| 资源进入科研任务 | `resource_use_in_task` | 目标任务可看到已关联资源 |
| 课题概览可定位业务对象 | `research_overview_tab_change` | 成员、任务和产出均可从 Tab 定位 |
| 任务可继续执行 | `research_task_open` / `research_task_action` | 从概览清单进入正确任务并完成一次状态操作 |

原型级成功标准：关键页面可达率 100%；P0 核心跳转无死链；列表、筛选、Tab 和任务执行均能完成一条本地闭环；关键页面无未处理控制台错误。

## 12. 优先级

### P0：最小完整闭环

- 公共门户完整模块及关键跳转。
- 集团科研资源中心的浏览、搜索、分类、筛选和详情。
- 我的资源的四种关系视图、类型筛选和核心操作。

## 15. 验收标准

### 15.1 导航和路由

- `/` 不再直接跳转 `/workspace`。
- 公共门户、集团科研资源中心和我的资源入口可达。
- 科研空间默认打开课题概览。
- 科研空间左侧只显示课题概览、科研任务、科研活动、科研资产四个二级入口。
- “空间管理”不再出现在用户可见导航和页面中。

### 15.2 业务闭环

- 用户可从门户浏览集团资源，登录后查看本人资源关系。
- 资源可申请、收藏、管理或加入任务，并在对应页面看到状态变化。
- 课题概览的四个 Tab 都可切换，刷新后保留当前 Tab。
- 任务列表可进入正确的科研任务执行工作区。
- 任务工作区可切换任务/会话，查看执行状态、人工确认、产出和引用资料。
- 科研产出只在确认、版本化或发布流程后进入科研资产。

### 15.3 界面和可用性

- 新页面与当前项目蓝白风格一致，不出现参考图红色主操作或异构导航。
- 页面在 1280×900、1440×900、1920×1080 下不出现主页面水平溢出。
- 所有可点击元素具有悬停、焦点、按下、禁用和必要的加载反馈。
- 横向 Tab、搜索、筛选、资源卡和表格操作支持键盘访问和可见焦点。
- 所有状态都有文字标识，不只依赖颜色。

## 16. 主要风险与控制

| 风险 | 控制方式 |
| --- | --- |
| 我的资源、集团资源和科研资产概念重叠 | 保持三个独立入口和读模型，使用统一底层数据 |
| 概览任务 Tab 与科研任务模块重复 | 概览 Tab 只做清单与入口；二级模块负责真实执行 |
| 删除空间管理破坏权限与成员数据 | 先分离用户界面和底层数据，只删除前者 |
| 直接复制静态原型导致架构分裂 | 按现有 React 组件、路由、状态与设计 token 重建 |
| 原型数字被误解为真实生产数据 | 统一标识演示数据，不声称已连接生产数源 |
| 门户视觉过度营销化、与应用风格断裂 | 保留门户空间感和数字孪生主视觉，但统一色彩、字体、圆角和图标语言 |

## 17. 本轮固定假设

- “我的资源”作为登录后全局一级模块，不放在科研空间下。
- 集团科研资源中心是公共页，登录后在同一页增加个人权限和操作。
- 课题概览四个 Tab 采用同一页头、同一路由主体加 URL 参数，不作为左侧第三级导航。
- 课题成员、任务和产出 Tab 优先展示完整列表，不在“科研信息”Tab 内重复展示大型列表。
- 本次先使用项目现有本地数据和状态容器完成前端闭环，不更换后端或权限架构。
- 本次不新增前端框架、UI 框架或交互库。
