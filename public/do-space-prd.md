# 0. 文档目的

本 PRD 用于统一「做空间」的产品定位、总体信息架构、页面体系、实验方案 Agent 工作模式、实验执行协同、样品/设备/预约/实验管理/表征分析等专业工作台边界，以及与 ELN、LIMS、iLOMS/设备纳管系统等既有系统的集成关系。

本版本明确：

> **做空间的智能入口以“实验方案设计与生成”为核心。**

实验样品、设备、仪器预约、实验管理和表征分析属于实验执行与管理工作台；  
“实验自动编排智能体”属于实验方案定版后的执行阶段能力，而不是与“实验方案设计 Agent”同级的首页主入口。

后续 UI 设计以本 PRD 为主要页面与交互依据。

# 1. 产品定位

## 1.1 做空间是什么

做空间承接读空间形成的研究问题、科学假设和证据，以及算空间产生的候选方案、参数和计算结果，将其进一步转换成：

> **可审核、可执行、可追溯的实验方案与实验任务。**

产品定位：

> **以实验方案设计与生成为智能入口，以样品、设备、预约、实验执行和表征分析为专业工作台，连接科研认知、计算验证与真实实验验证。**

核心链路：

```text
研究目标 / 科学假设 / 计算结果
   ↓
实验目标理解
   ↓
实验方案设计
   ↓
方案比较与参数确定
   ↓
人工审核 / 会签 / 定版
   ↓
进入实验执行
   ↓
实验自动编排
   ↓
样品准备
   ↓
设备匹配与仪器预约
   ↓
实验执行与过程记录
   ↓
原始数据采集
   ↓
实验表征分析
   ↓
实验结论
   ↓
回流算空间优化 / 回流读空间补充研究
```

# 2. 做空间解决的核心问题

1. **如何把科研目标转成可执行实验方案？**
2. **实验步骤、参数范围、材料、样品、设备怎么确定？**
3. **AI 生成的实验方案如何人工审核、会签和定版？**
4. **实验方案如何衔接样品、设备、预约和执行？**
5. **实验过程中出现异常时如何处置？**
6. **实验原始数据和实验记录如何与 ELN/LIMS/设备系统关联？**
7. **实验结果如何进行表征分析和科学解释？**
8. **实验结果如何回流算空间继续优化？**

# 3. 产品设计原则

## 原则 1：首页主 Agent 只聚焦实验方案设计与生成

做空间首页的核心不是“设备管理门户”，而是：

> **实验方案设计与生成 Agent**

首页强调：

- 输入实验目标
- 引用读空间结论
- 引用算空间结果
- 上传已有实验方案
- 选择实验模板
- 生成候选实验方案

样品、设备、预约、实验管理等作为“实验执行工作区”进入。

---

## 原则 2：AI 生成方案 ≠ 允许自动开展实验

实验方案必须经过人工确认。

AI 可以：

- 建议实验步骤
- 建议参数
- 推荐设备
- 提醒风险
- 生成候选方案

但不能默认：

- 自动下发危险实验
- 自动解除审批
- 自动启动设备
- 自动调整高风险参数

---

## 原则 3：实验方案是做空间的关键 Artifact

在正式实验任务之前，必须形成结构化：

> **Experiment Plan**

而不是一段自然语言方案。

---

## 原则 4：设计阶段与执行阶段分离

### 设计阶段

由：

> 实验方案设计与生成 Agent

负责。

### 执行阶段

由：

> 实验自动编排智能体 + 专业实验工作台

负责。

---

## 原则 5：不重复建设既有实验系统

AI4S 侧重点：

- 科研任务上下文
- 方案生成
- 方案与课题关系
- 方案版本
- 跨系统对象关联
- 实验进度汇聚
- 结果回流

既有系统继续作为权威来源：

- ELN：实验记录
- LIMS：样品/检测/实验数据等
- iLOMS/设备纳管系统：设备台账、状态、设备数据
- 预约系统：预约规则、审批、排期

---

# 4. 功能基线与产品化映射

当前做空间原始功能共 7 项：

| 原功能 | 产品化形态 | 核心定位 |
|---|---|---|
| 实验方案设计 | Experiment Design Agent | 做空间统一智能入口 |
| 实验样品与记录 | Sample & ELN Workspace | 样品、批次、记录与 ELN 集成 |
| 实验设备纳管与共享 | Equipment Workspace | 设备信息、状态、能力与共享 |
| 实验仪器预约 | Instrument Booking Workspace | 设备可用性、预约与机时 |
| 实验自动编排智能体 | Experiment Orchestration Agent | 方案定版后的执行编排 |
| 实验管理 | Experiment Management Workspace | 批次、进度、运行与异常 |
| 实验表征分析 | Characterization Analysis Workspace | 原始结果、分析、解释与报告 |

# 11. 页面 04｜实验自动编排任务页

## 11.1 页面定位

> 将已定版实验方案转换成实验执行任务，对样品、设备、人员、预约、审核、状态和异常进行协同编排。

该 Agent 只在实验方案定版后进入。

---

## 11.2 执行链路

```text
实验方案定版
   ↓
生成实验任务
   ↓
检查样品条件
   ↓
匹配设备
   ↓
检查设备可用时间
   ↓
仪器预约
   ↓
确认责任人
   ↓
实验前审核
   ↓
任务下发
   ↓
实验执行
   ↓
状态监控
   ↓
结果回传
```

---

## 11.3 页面建议

三栏结构：

```text
左：实验任务与依赖
中：编排过程 / 人工确认
右：执行计划 / 状态
```

---

## 11.4 人工确认节点

必须确认：

- 正式预约设备
- 实验任务下发
- 高风险实验
- 参数变更
- 暂停/恢复
- 异常后继续执行

# 17. 读 → 做

读空间可传入：

- 研究目标
- 科学假设
- 文献方法
- 文献参数

- 证据
- 研究空白

# 18. 算 → 做

算空间传入：

- 计算目标
- 候选方案
- 推荐参数
- 敏感参数
- 模拟结果
- 风险/约束
- 计算结果 Artifact

例如：

```text
验证目标
检验温度和围压对裂缝破坏模式的影响

推荐实验参数
温度：25–200℃
围压：10–50MPa

重点关注
温度 > 150℃ 时的破坏模式变化
```

---

# 19. 做 → 算

实验完成后可：

> **用于模型校准 / 重新计算**

传递：

- 实验真实参数
- 实验结果
- 表征数据
- 偏差
- 异常样本

---

# 20. 做 → 读

如果实验结果出现新现象：

> **补充文献研究**

传递：

- 实验异常现象
- 参数条件
- 新科学问题
- 需要检索的方向

# 29. UI 阶段重点验证问题

1. 做空间首页是否足够聚焦“实验方案”，没有被设备/预约功能稀释。
2. 实验方案 Agent 的右侧 Artifact 是否支持足够大的方案编辑区域。
3. 多方案比较是 Agent 页中的 Tab 还是独立全屏。
4. 方案版本与会签是否采用独立详情页。
5. 实验自动编排是否使用时间线、流程图还是任务清单为主。
6. 样品和设备页面需要展示多少来自来源系统的字段。
7. 预约是否在 AI4S 内完成还是跳转来源系统。
8. 实验管理与 ELN 的边界是否足够清晰。
9. 表征分析是否需按油气/材料/合成生物形成专业插件。
10. AI4S 是否展示实时设备数据，还是只展示授权摘要。

# 31. 做空间一句话总结

> **做空间以实验方案设计与生成为统一智能入口，以 Experiment Plan 为核心科研 Artifact，在人工审核和定版后，通过实验自动编排连接样品、设备、预约和实验执行，并将实验记录与表征结果回流科研上下文，最终实现“读—算—做—析—优”的科研闭环。**
