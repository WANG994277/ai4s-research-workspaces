# 0. 文档目的

本 PRD 用于统一「算空间」的产品定位、总体信息架构、页面体系、科研计算 Agent 工作模式、专业工作台边界、计算任务生命周期、数据/模型/工具协同、科研 Artifact、结果分析与跨空间流转关系。

算空间不按传统“科学软件导航 + 任务列表 + 算力管理”方式组织，而采用：

> **科研问题驱动 + 科研计算助手 Agent + 专业计算工作台 + 统一计算任务生命周期 + Artifact 科研产物 + Research Context 科研上下文**

的产品形态。

算空间的核心不是“提供软件入口”，而是：

> **把一个科研问题或科学假设转化为可执行、可追溯、可评价的计算方案，并组织数据、模型、工具、软件和资源完成求解。**

后续 UI 设计以本 PRD 为主要页面与交互依据。

# 1. 产品定位

## 1.1 算空间是什么

算空间是 AI4S 科研平台中承接「读空间研究结论」并向「做空间实验验证」过渡的核心计算环境。

其产品定位为：

> **面向科研人员，将科研问题、科学假设和已有研究结论转化为计算目标、计算方案和可执行任务，统一调用科研数据、科研模型、科学软件、算法工具和计算资源，完成设计筛选、模拟计算、模型训练、结果分析与评价。**

典型主链路：

```text
科研问题 / 科学假设
   ↓
计算目标理解
   ↓
计算方案规划
   ↓
数据 / 模型 / 工具 / 软件选择
   ↓
参数与约束配置
   ↓
资源申请与任务创建
   ↓
运行执行
   ↓
日志与状态
   ↓
计算结果
   ↓
结果分析与评价
   ↓
形成科研结论
   ↓
进入做空间实验验证 / 返回读空间补充研究
```

---

## 1.2 算空间解决的核心问题

用户进入算空间，主要解决以下问题：

1. **这个科研问题应该怎么算？**
2. **应该选用什么数据、模型、方法和专业软件？**
3. **关键参数应该怎么设置？**
4. **是否需要设计多组候选方案或参数组合？**
5. **计算任务如何提交、运行、监控和复现？**
6. **不同候选方案或模型的结果如何比较？**
7. **哪些计算结果可以转化为实验验证方案？**
8. **如何沉淀可追溯的计算方案、数据版本、模型版本和结果产物？**

---

## 1.3 产品设计原则

### 原则 1：科研计算助手是统一智能入口，但不是替代所有工作台

适合 Agent 承载：

- 科研计算问题理解
- 计算目标澄清
- 计算方案生成
- 方法推荐
- 工具推荐
- 参数建议
- 资源建议
- 计算任务草稿创建
- 结果解释
- 下一步建议

适合专业工作台承载：

- 智能设计与筛选
- 参数批量配置
- 计算任务管理
- 运行日志
- 数据处理流程
- 模型训练
- 模型评价
- 工具/软件上架与管理
- 结果图表与对比分析

---

### 原则 2：Agent 负责“想、规划、调用”，Workspace 负责“配置、执行、管理”

统一规则：

> **Agent 负责理解科研问题、规划计算路径、推荐能力并生成任务草稿；专业工作台负责精细参数配置、批量操作、长任务运行、状态管理和结果分析。**

---

### 原则 3：计算方案必须先于计算任务

用户输入：

> “帮我模拟不同温度对催化剂稳定性的影响。”

系统不应立即提交计算任务。

应先形成：

> **计算方案 Artifact**

包括：

- 研究目标
- 计算方法
- 输入数据
- 变量
- 固定参数
- 软件/模型
- 输出指标
- 资源建议
- 风险/约束

用户确认后，再创建正式计算任务。

---

### 原则 4：长任务不在聊天流中执行

计算任务、数据处理任务和模型训练任务可能持续分钟、小时甚至更长。

因此：

- Agent 页面负责创建任务、解释任务和查看摘要
- 专业任务页负责运行状态、日志、资源、产物和异常处理

不要把实时日志刷在对话区。

---

### 原则 5：所有计算结果必须可追溯

计算结果需关联：

- 来源科研任务
- 输入数据版本
- 模型版本
- 工具/软件版本
- 参数
- 运行环境
- 资源配置
- 运行时间
- 任务日志
- 输出产物
- 人工确认记录

---

### 原则 6：复用 AI 中台，不重复建设底层平台

算空间负责：

- 科研任务语义
- 课题上下文
- 数据/模型/工具引用关系
- 任务入口与结果回流
- 科研计算方案
- 科研结果组织

底层能力尽量复用：

- 数据处理服务
- 模型训练与微调
- 模型管理
- 算力资源
- 任务队列
- 镜像与环境
- 调度与运行
- 通用评测能力

# 2. 功能基线与产品化映射

当前算空间原始功能共 6 项：

| 原功能 | 产品化形态 | 核心定位 |
|---|---|---|
| 科研助手（科研计算求解） | Compute Agent | 统一科研计算入口 |
| 智能设计与筛选 | Design & Screening Workspace | 多目标设计、候选生成与虚拟筛选 |
| 智能计算模拟任务 | Compute Task Workspace | 计算任务全生命周期 |
| 科研数据处理 | Data Preparation Workspace | 数据准备、处理、版本与结果回流 |
| 科研模型训练与评价 | Model R&D Workspace | 模型训练、版本管理与科学评价 |
| 工具/软件集成 | Scientific Tools Marketplace + Tool Management | 科研工具/软件发现、使用、接入、发布与版本管理 |

# 6. 页面 01｜算空间首页

## 6.1 页面定位

算空间首页是：

> **科研计算任务的统一智能启动页。**

用户进入后主要完成：

1. 描述一个需要解决的计算问题；
2. 引用读空间已有研究结论；
3. 上传/选择科研数据；
4. 启动科研计算助手；
5. 进入智能设计、任务、数据、模型或工具工作台；
6. 继续历史计算任务。

---

## 6.2 页面标题

标题：

> **开始计算**

副标题：

> 将科研问题转化为可执行计算方案，调用数据、模型与科学工具完成验证。

---

标题：

> **今天想解决什么计算问题？**

# 7. 页面 02｜科研计算助手 Agent

## 7.1 页面定位

> 将科研计算意图转化为可编辑、可确认、可执行的计算方案，并协调数据、模型、工具与任务创建。

沿用读空间统一 Agent Workspace 三栏框架：

```text
┌───────────────────────────────────────────────────────────────┐
│ 当前课题 / 当前计算问题 / 任务状态 / 保存方案 / 创建任务      │
├──────────────┬──────────────────────────────┬─────────────────┤
│ 左栏         │ 中栏                         │ 右栏            │
│ 任务与上下文 │ Agent 执行区                 │ 计算方案        │
│              │                              │ Artifact        │
│ 计算目标     │ 问题澄清                     │                 │
│ 任务计划     │ 方案规划                     │ 输入数据        │
│ 数据/模型    │ 工具推荐                     │ 方法            │
│ 工具/软件    │ 参数建议                     │ 参数            │
│              │ 人工确认                     │ 输出指标        │
└──────────────┴──────────────────────────────┴─────────────────┘
```

---

## 7.2 典型任务计划

```text
✓ 1. 明确计算目标
✓ 2. 识别输入与约束
● 3. 推荐计算方法
○ 4. 推荐工具/软件
○ 5. 生成参数方案
○ 6. 评估资源需求
○ 7. 生成计算方案
○ 8. 创建计算任务
```

---

## 7.3 计算方案 Artifact

建议固定为结构化形式：

```text
科研计算方案 V1

研究目标
验证高温和高围压对页岩裂缝扩展机制的影响

计算目标
预测不同温度/围压组合下的裂缝方向和应力分布

输入数据
页岩材料参数集 V3

计算方法
热-力耦合有限元模拟

推荐工具
COMSOL Multiphysics

变量
温度：25–250 ℃
围压：10–60 MPa

固定参数
弹性模量：...
泊松比：...

输出指标
裂缝扩展方向
最大主应力
塑性区
破坏模式

评价方式
与文献实验结果对比

资源建议
CPU 32核
内存 128GB

来源
科学假设 H1
文献 6篇
```

操作：

- 修改方案
- 生成新版本
- 查看依据
- 创建计算任务
- 保存为科研方案

---

## 7.4 Agent 推荐工具时必须可解释

例如：

> 推荐 COMSOL。

需要说明：

```text
推荐原因

• 支持热-力耦合
• 已接入当前科研平台
• 当前课题可使用对应许可证
• 可输出目标所需应力场和温度场
```

---

## 7.5 参数推荐

参数来源应区分：

- 文献参数
- 实验参数
- 领域默认值
- AI 推荐值
- 人工输入值

示例：

| 参数 | 值 | 来源 | 状态 |
|---|---:|---|---|
| 弹性模量 | 28 GPa | Paper A | 已引用 |
| 泊松比 | 0.24 | 实验数据集 V2 | 已确认 |
| 温度范围 | 25–250℃ | AI建议 | 待确认 |

---

## 7.6 人工确认节点

建议以下行为必须确认：

- 计算方法选择
- 高成本资源申请
- 软件许可证调用
- 大批量参数组合
- 正式创建任务
- 模型训练
- 结果转为实验方案

# 32. 下一步 UI 设计顺序

建议按照以下顺序生成高保真 UI：

1. **算空间首页**
2. **科研计算助手 Agent 任务页**
3. **智能设计与筛选工作台**
4. **智能计算模拟任务中心**
5. **计算任务详情页**
6. **科研数据处理工作台**
7. **科研模型训练与评价工作台**
8. **科研工具 / 科学软件广场**
9. **科研工具详情页**
10. **工具接入/发布管理页**

第一批建议优先生成前 5 张，用于验证：

> **科研问题 → 计算方案 → 正式计算任务 → 结果 → 做空间**

这条核心链路是否成立。

# 33. 算空间一句话总结

> **算空间以科研问题和科学假设为输入，以科研计算助手为智能入口，以计算方案为关键中间产物，以设计筛选、任务执行、数据处理、模型研发和科研工具为专业工作台，通过可追溯的计算任务生命周期形成计算结果 Artifact，并最终将结果回流至读空间或转入做空间进行实验验证。**
